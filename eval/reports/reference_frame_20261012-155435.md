## 2. reference_frame 变化评测集构造（`eval/generate_reference_frame.go` 新增）

### 2.1 设计要点

| 项 | 实现 | 说明 |
|---|---|---|
| 样本数 | **60 条**（30 组 × 2 条：qA / qB） | ≥ 50 达标 |
| 桶标签 | `reference_frame` | run_kpi.go 新增桶统计 |
| 构造方式 | **模板替换**（纯文本，不调 LLM） | 任务书 B.3.1 允许 |
| seed | 42 固定 `rand.New(rand.NewSource(42))` | 无 `time.Now()` / map 迭代序 |
| build tag | `//go:build ignore` | 独立生成器，不进入主包 |

### 2.2 核心构造逻辑（关键设计）

为了**隔离 reference_frame 信号的区分度**，三候选采用**严格对照**：

- **fact 文本完全一致**（如 `"客户A的偏好是周一"`），仅 `ReferenceFrame` 坐标不同（entity / project / scene 三坐标差异化）。
- 这样 keyword（BM25）、semantic（char n-gram）、entity 三路信号在候选间**无法区分**（文本相同），排序只能由 reference_frame 信号决定。
- **target memory id 命名含 `Z`**（字典序最大）。RRF 融合在信号分 tie 时按 MemoryID 升序排序，Z 必然排最后——当 reference_frame 权重为 0 时 target **必然 miss**，形成严格对照。

每条样本使用**独立 memory id**（qA / qB 后缀），避免评测器写入同组时触发 `ErrIdempotentNoop` 被跳过（R3-A 评测集曾踩此坑）。

### 2.3 输出

- **文件**：`eval/dataset/reference_frame.jsonl`（60 条）
- **每条字段**：query / expected_memory_id / memory（fact + ReferenceFrame 坐标）/ distractor_memories ×2（同 fact 不同坐标）

## 3. reference_frame 信号复检（R3-A §8 风险表结论修正）

### 3.1 对照组设置

| 权重文件 | reference_frame 权重 | 说明 |
|---|---|---|
| `rank_weights_en_r2.json` | **0.0** | R2-A 快照（R3-A 沿用） |
| `rank_weights_en_r4b_ref.json` | **4.0** | R4-B 对照：其余与 r2 一致 |

### 3.2 实测结果

| 指标 | rf=0.0（R2/R3-A 现状） | rf=4.0（对照） | 变化 |
|---|---|---|---|
| 评测集总数 | 60 | 60 | — |
| 总体 MRR | 0.245 | **0.692** | +0.447 |
| ref 桶 MRR | 0.245 | **0.692** | +0.447 |
| 桶准确率（memory_id） | 100% | 100% | — |
| **期望记忆 ref 分在候选集最高**（信号区分度） | **100%** | **100%** | **信号区分度 = 100%** |
| **期望记忆最终 top-1 命中率** | **0%** | **43.3%** | +43.3pp |
| ref 分最高且 top-1 命中（信号→命中传导率） | **0%** | **43.3%** | +43.3pp |
| rank 分布 | {3:28, 6:28, 8:2, 4:1, 5:1} | 大量 top-1 | 排序显著前移 |

### 3.3 诊断证据（`-diag-ref` 打印）

对样本 `ref-000Z-qA`（期望）：
- 期望记忆 ref 分 = **1.0000**，但排在 **#3**（rf=0.0 时）。
- 原因：keyword/semantic/entity 三信号在文本相同的三候选间**打分完全相等**（tie），RRF 融合后靠 MemoryID 升序 tie-break，`Z` 字典序最大 → 排最后。
- 这正是 R3-A 观察到"信号无区分度"的**表面现象**：区分度是存在的（ref 分有差异），只是被权重 0.0 抹平。

### 3.4 结论（明确）

> **reference_frame 信号本身有 100% 区分度**——在 fact 文本完全一致、仅坐标不同的三候选间，期望记忆的 ref 分恒为最高。
> **当前权重（rf=0.0）把信号关闭了**，导致 top-1 命中 0%。
> **抬到 rf=4.0 后 top-1 命中恢复到 43.3%**，桶 MRR 从 0.245 升到 0.692。
>
> **对 R3-A §8 的修正**：信号不是"无价值"，而是**权重被校准为 0.0 而未参与排序**。R3-A 搜索阶段看到合成集 `QueryFrame` 恒空、公开集恒匹配（无方差），因此权重坐标下降时落到 0.0——但这反映的是**当时评测集形态**（无 reference_frame 变化样本）**无法提供区分度信息**，而非信号本身无能力。**建议 P8 或后续在权重搜索时把 reference_frame 纳入可变量**，并基于本评测集（60 条）重新校准。

## 4. 合成集 fact/top-1 波动诊断（isolate 实验）

### 4.1 波动复现（R3-A §8 风险表原文）

R3-A §8 记录：合成集 fact **96.6% → 95.8%（−0.8pp）**，合成集 top-1 **68.3% → 67.5%（−0.8pp）**，由 R2（`da77a8d`）→ R3-A（`1dc9d05`）引入。

注：R3-A 的 fact 96.6% 记录在 v3 口径下；当前评测器 fact 已升级 v4（R3-C），本报告 isolate 实验统一用 `-fact-v4=false` 复现 v3 口径，**保证与 R3-A 数字可比**。v4 口径下波动幅度略收窄（97.5%→97.0%，−0.5pp），**趋势与根因一致**。

### 4.2 isolate 实验矩阵

在合成集（530 条 fact 口径 / 570 条 MRR 口径）上做 2×2 isolate：embedder（开/关）× 权重（R2 / R3-A）。

| 组 | embedder | 权重 | 主 fact（v3 口径） | 总体 MRR | single-hop MRR | top-1 命中 |
|---|---|---|---|---|---|---|
| **A**（R2 基线） | 关 | R2 (`rank_weights_en_r2.json`) | **97.5%**（517/530） | 0.846 | **0.963** | **69.25%**（367/530） |
| **B**（R3-A 现状） | 开 | R3-A (`rank_weights_en.json`) | **97.0%**（514/530） | 0.843 | **0.947** | **68.68%**（364/530） |
| **C**（isolate 权重） | 关 | R3-A | **98.5%**（522/530） | **0.851** | **0.973** | **70.19%**（372/530） |
| **D**（isolate embedder） | 开 | R2 | **96.0%**（509/530） | **0.839** | **0.930** | **67.74%**（359/530） |

### 4.3 根因定位

**对比 A vs D**（仅切换 embedder，权重固定 R2）：
- fact：97.5% → **96.0%（−1.5pp）**
- top-1：69.25% → **67.74%（−1.5pp）**
- single-hop MRR：0.963 → **0.930（−0.033）**
- 总体 MRR：0.846 → **0.839（−0.007）**

**对比 A vs C**（仅切换权重，embedder 固定关）：
- fact：97.5% → **98.5%（+1.0pp）**
- top-1：69.25% → **70.19%（+0.94pp）**
- single-hop MRR：0.963 → **0.973（+0.010）**
- 总体 MRR：0.846 → **0.851（+0.005）**

**根因结论**：
1. **fact / top-1 波动的根因是 R3-A 引入的 char n-gram embedder**，不是权重。单独接入 embedder（组 D vs A）即造成 fact −1.5pp、top-1 −1.5pp、single-hop MRR −0.033。
2. **权重变更（R2 → R3-A）反而是正向的**：单独切换权重（组 C vs A）带来 fact +1.0pp、top-1 +0.94pp。R3-A 的权重校准对合成集**有益**。
3. **embedder 为何在合成集上拖累**：R3-A 的 char n-gram 词表（dim=6817）由**公开基准语料 + 合成集语料联合构建**（`collectVocabCorpus`），但合成集查询文本与公开集风格差异较大（合成集是模板生成的中文/英文混合短句，公开集是 LongMemEval/BEAM 长对话）。char trigram 对公开集长文本效果好，但对合成集短模板查询引入**与 keyword 冲突的排序偏差**，导致部分样本 top-1 从正确记忆偏到错误记忆。
4. **总体 MRR 波动极小**（−0.007 ~ +0.005），说明波动集中在 single-hop 桶（R3-A 记录 top-1 68.3%→67.5% 正是 single-hop 主口径）。

## 5. `-now-asof-default` 默认开启评估

### 5.1 变更内容（`eval/run_kpi.go`）

新增 flag：
```go
nowAsOfDefault := flag.Bool("now-asof-default", false,
    "R4-B: 默认开启 -now-asof（as_of 查询时 rf.Now=样本 as_of）；false 时按 -now-asof 原样")
```
生效逻辑：`nowAsOfOn = *nowAsOf || *nowAsOfDefault`（R3-B 的 `-now-asof` 显式开关仍优先）。

### 5.2 实测回归

| | single-hop MRR | 0.9867 | 0.987 | ✅ |
| | multi-hop 主 MRR（口径 C） | 0.9599 | 0.960 | ✅ |
| | multi-hop 口径 A | 0.9455 | 0.945 | ✅（A 路负责） |
| | open-domain MRR | 0.9119 | 0.912 | ✅ |
| | temporal MRR | 0.9940 | 0.994 | ✅ |
| **合成集** | 总体 MRR | **0.8434** | **0.843** | ✅ 不回归 |
| | single-hop MRR | 0.9467 | 0.947 | ✅ |
| | multi-hop 主 MRR | 0.500 | 0.500 | ✅ |

### 5.3 结论

`-now-asof-default` 开启后公开/合成 MRR **无回归**（均在四舍五入误差内）。该默认值可安全开启，使 as_of 时序一致性成为默认行为（R3-B §6 决策由"默认 false"升级为"默认 true，可 `-now-asof=false` 关闭"）。
