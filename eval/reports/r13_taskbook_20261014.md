### A 路 — 融合算子与跨 Agent 参考系对齐（建议 2 + 建议 5）

**目标**：把 Monty 的两条高价值机制落到 VoteFusion 与多 Agent 共享路径，改动小、安全相关、收益直接。

**背景**：
- 建议 2：Monty 特征证据 `clip(tolerance - diff, 0, inf) / tolerance`——**不匹配记 0，绝不扣负分**；半径内取 max 而非平均。lightmem §3.4 的 rank 融合已接近，但缺"只加不减"与"相对容差"的显式定义。
- 建议 5：Monty 中 vote 是"相对发送者身体"的，接收方必须变换到**自己**参考系；投票不是 bag-of-features，依赖特征在世界的相对排布。lightmem §3.2 `shared_user` 让同用户下多 Agent 共享，但**同一事实在不同 Agent 的 entity/scene 语境下可能指代不同**。

**范围**：

### B 路 — 记忆位移边与关系式检索（建议 1）

**目标**：把参考系从"扁平坐标"升级为"带位移边的记忆图"，支撑多跳召回与关系推理。

**背景**：
- Monty graph memory：节点 = `pose + features`，**边 = displacement**（从 A 到 B 需要的关系/动作）。
- lightmem 现状：§3.2 是一组独立维度，**记忆之间没有关系**，多跳召回只能靠向量相似度近似。
- 建议 1 价值最高，但需配套存储与容量治理；红线要求**只增不改 Schema**，故边表作为**新增扩展表**，L1 默认不建边，仅 L2 长期记忆建边。

**边的构建触发规则（R13 本期最小可用集，纯启发式，不调 LLM）**：
- 触发时机：L2 记忆写入时，与同 entity / 同 scene / 同 task_id 的近期 L2 记忆做离线规则配对。
- relation 判定（四类枚举来源 monty.md 建议 1）：
  - `temporal`：两条记忆 `created_at` 间隔 ≤ 7 天，且属于同一 task / session；初始 weight = 0.3。
  - `task-flow`：两条记忆挂在同一 task_id 下，按时间先后建边；初始 weight = 0.4。
  - `causal`：同 user 下，后一条记忆的 `fact` 字符串中出现前一条 entity 的指代（如"它/该/这个"，简单字符串匹配）；初始 weight = 0.5。
  - `entity-alias`：两条记忆 `entity` 经归一化（小写、去标点）后相同；初始 weight = 0.8。
- 写入幂等：`(from_memory_id, to_memory_id, relation)` 三元组唯一，重复写入不新增行。
- 本期不做：跨语料挖掘、人工标注界面、用户反馈修正、weight 在线学习——全部留到后续轮次。

**范围**：

|---|---|---|---|
| B.1 | 位移边 Schema 与存储 | `kernel/displacement_edge.go`（新增） | 边表字段：`from_memory_id` / `to_memory_id`（ULID）、`relation`（`causal`/`temporal`/`task-flow`/`entity-alias`，来源 monty.md 建议 1）、`weight` [0,1]、`created_at`（只增）、`invalidated_at`（软删除时间戳，默认 NULL）；写入接口幂等（三元组唯一），不覆盖历史——淘汰边通过置 `invalidated_at` 实现，不物理删除 |

| B.5 | 合并度指标（监控实体消解质量） | `eval/polaris/polaris_mergence.go`（新增，`//go:build ignore` + `package main`，import `github.com/lightmem/kernel`） | 定义两个指标，跑 holdout_v2 输出基线数值：① `mean_edges_per_memory` = 边总数 / L2 记忆数（R13 首次跑时若边表为空则为 0，作为后续建边质量的对照基线）；② `mean_memories_per_entity` = 按 entity 字符串归一化（小写去标点）分组后，每组记忆数的均值——**本期 B 路自走极简字符串分组，不依赖 A.3 的 entity_align 函数**，两路保持独立 |
