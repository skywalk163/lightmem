## 1. 本轮要补的缺口

R14 及以前，§7.5「注入降权」只有**处置**、没有**检测**：`kernel/writepolicy.go`
的 `PoisoningGuardPolicy` 按 `provenance=prompt_injection_suspect` 判降权，
但全库没有任何组件会给记忆打上这个标签——**标签无人产生，处置恒不触发**，
应用层这道防线实际处于空转。本轮补上检测端，并把检测与处置显式分离，
做到可测（有语料、有指标、有报告、有门禁）。

## 3. 检测器口径

- **规则表**：16 条正则模式，按 ID 字典序静态声明（中文 8 / 英文 8），
  另加 1 条变体改写检测（零宽字符、不可见格式字符、等价空白），共 17 条命中来源。
  单条规则的严重度与权重：低危（工具滥用、跨 Agent 传播）0.25–0.40，
  高危（直接指令、指令输出、角色劫持、间接面引用）0.60–0.80。
- **输出**：`InjectionVerdict{Severity, Score, Signals, Quote}`。
  `Score` 为命中规则权重之和，上限 1.0；高危规则命中即可达高危阈值。
  `Quote` 取首个命中位置附近的片段（≤200 rune），供人工复核。
- **确定性**：不读时间、不用随机源、不依赖 map 迭代序，规则顺序由字典序固定，
  Signals 显式排序——同一输入恒得同一输出（红线 5）。
- **两阶段**：`DetectInjection` 只出判定；`MarkSuspect` 只置
  `provenance=prompt_injection_suspect`，高危时把 `confidence` 压到 0.3 上限。
  不改正文、不丢弃记忆——检测恒常运行，处置可配置。
- **可选加权**：`DetectConfig.IndirectMode` 对引文/证据块形态（跨 Agent 转述、
  粘贴的外部文本）加权；`EnableRepeat` 对同一主体重复出现的同型注入加权。
  二者默认关，由调用方显式选择。
- **扫描范围**：全量扫描，不设截断上限。RE2 无回溯、线性时间，
  检测成本与正文长度成正比；若截断，长正文尾部追加的注入会变成确定性盲区，
  而尾部追加正是真实投毒的主要形态。

## 4. 语料口径

- **对抗语料 342 条 / 17 类**：中文 8 类（直接指令、指令输出、否定式、
  持续改写、跨 Agent 转述、角色劫持、工具滥用、跨 Agent 传播）、
  英文 8 类（同构）、引文块间接注入 1 类；每类 20 条，另加 2 条零宽变体。
- **良性近似 300 条 / 15 类**：刻意贴近规则字面但语义无害，例如
  「该笔费用忽略不计」「请记住这份合同」「请输出系统时间」「请执行已知函数」
  「同步到共享文件夹」「另一个 agent 提供的参考数据」「请忽略上面的草稿」。
- **`provenance` 一律留空**：检测器只看正文，不读注入方标注；
  语料生成脚本与检测器完全解耦，避免「脚本知道答案」。
- 语料为**合成对抗样本**，不进入北极星 holdout（北极星分母只含真实 query）。

评测命令（0.88）：

```sh

  -benign  eval/dataset/benign_near.jsonl \
  -report r15a_injection -reports-dir eval/reports -now-fixed 2026-10-15
```

| 指标 | 值 | 说明 |
|---|---|---|
| recall | **1.0000** | 342 / 342 对抗样本全部命中 |
| precision | **1.0000** | 342 条命中全部为对抗样本 |
| false_positive_rate | **0.0000** | 300 条良性近似零误报 |
| severity 分布 | high 260 / low 82 / none 300 | 342 命中按严重度分桶 |

按模式：19 个对抗 pattern 的 detected/total 全部 100%（17 类 × 20 条 + 2 条变体）；
15 个良性 pattern 的 fp 全部为 0。按规则：17 条规则全部有命中，无「从未触发」规则，
无「永远误报」规则。报告 JSON：`eval/reports/r15a_injection_2026-10-15.json`。

**指标解读的边界**：以上数字是自建对抗语料上的结果，
**不代表真实攻击面的检出能力**。真实样本集上的检出率需人工标注语料单独验证。

## 8. 未验证项与已知限制

1. **真实攻击面未测**：语料为合成对抗样本，真实投毒样本（跨语言、混合脚本、
   长上下文诱导、编码绕过）的检出率未知。§7.5.1 已如实写入该边界。
2. **门禁未纳入本轮新增文件**：`scripts/gate.sh` 的 [1]（NEW_GO）与
   [6]（NEW_FILES）仍是 R14 硬编码清单（forgetting_drift / flush / edge_persist），
   未含 `poison_detect`。已用等价的手工命令补齐核验（§6 下），
   建议在 D 路把 gate.sh 扩到 12 项时一并补入。
3. **性能未基准**：本轮未做检测耗时 benchmark。全量扫描为线性成本，
   但 100KB 以上正文的耗时未实测，建议 R16 补基准并设上限告警线。
4. **语言覆盖有限**：规则表只覆盖中文与英文字面，日文、韩文、
   中英混合脚本、全角/半角混排的注入未覆盖（零宽变体检测可部分兜底）。
5. **版本表未同步**：`lightmem.md` 附录 B 版本表尚无 v2.4.2 行
   （R15-B 同样使用了 v2.4.2 但未登记）。为避免与并行路次冲突，本轮未改动版本表，
   留由汇总路次统一补一行。
6. **报告时间戳**：`generated_at` 取 `-now-fixed 2026-10-15`（确定性优先），
   不是实际运行时刻。
