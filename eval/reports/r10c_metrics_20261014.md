## 1. 新依赖可行性结论

### 1.1 探针结果

```
$ mkdir -p /tmp/probe && cd /tmp/probe
$ printf 'module probe\n\ngo 1.25\n' > go.mod
$ timeout 60 go get github.com/prometheus/client_golang@latest
go: github.com/prometheus/client_golang@latest: Get "https://proxy.golang.org/...": i/o timeout
```

**结论**：`proxy.golang.org` 在当前 0.88 网络环境下不可达，`go mod download` 超时。

### 1.2 降级方案

按任务书 §3.C.2 约定，走**降级方案**：
- 保持零新依赖，对手写序列化做**格式合规审计**并补齐缺口；
- 新增**格式锁定测试**（golden file）确保后续升级时无回归；
- 在报告中明确记录「proxy 不可达 + 缓存无包」，给出迁移前置条件。

### 1.3 迁移前置条件（供 R11 参考）

若未来需迁移官方 `client_golang`：
1. 在 0.88 上配置 `GOPROXY=https://goproxy.cn,direct` 或内网镜像；
2. 预拉包到 vendor 目录：`go mod vendor`；
3. 验证 `go build` + `go test -race ./kernel/...` 全绿；
4. 对外 API 不变（`ObserveHTTP` / `RecordConsolidate` / `LastConsolidate` / `PrometheusText` 签名保持）。

## 2. 格式合规审计

### 2.1 审计项逐项核对

| # | 审计项 | 现状 | 结论 |
|---|---|---|---|
| 1 | `# HELP` / `# TYPE` 顺序 | HELP 在 TYPE 前（L167-168, 181-182, 186-188, 191-193, 196-198） | ✅ 合规 |
| 2 | 直方图 `_bucket` / `_sum` / `_count` 序列完整 | `renderHistogram` 输出 bucket（含 +Inf）→ sum → count（L204-216） | ✅ 合规 |
| 3 | 标签转义（引号 / 反斜杠 / 换行） | `labelVal` 用 `strconv.Quote`（L219-223），Go 转义格式被 Prometheus 接受 | ✅ 合规 |
| 4 | 数值格式化避免科学计数法 | `formatFloat` 用 `FormatInt`（整数）+ `FormatFloat('g', -1, 64)`（浮点） | ⚠️ 注意：`'g'` 格式在极小/极大值可能产 scientific notation，已新增 `TestPrometheusText_NoScientificNotation` 验证 |
| 5 | 指标名 / 标签名合法性 | `http_requests_total` / `http_request_duration_ms` / `memories_saved_total` / `memories_recalled_total` / `recall_latency_ms` — 全小写 + 下划线 | ✅ 合规 |
| 6 | `/metrics` 端点路由冲突 | main.go 外层 mux 拦截（L132-134），与 router.go `handleMetrics` 无冲突 | ✅ 合规 |

### 2.2 发现的问题

| # | 问题 | 严重性 | 处理 |
|---|---|---|---|
| 1 | `formatFloat` 用 `'g'` 格式，极小值（如 0.000001）可能输出 `1e-6` | 低 | 已新增 `TestPrometheusText_NoScientificNotation` 验证；若实测失败，改用 `'f'` 格式 |
