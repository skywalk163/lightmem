## 2. 实现（`eval/run_kpi.go`）

### 2.1 新增 KPIReport 字段

```go
FactTotal         int    `json:"fact_total,omitempty"`          // 主 fact 口径分母（= total − template_total）
TemplateTotal     int    `json:"template_total,omitempty"`      // 模板 expected 样本数
TemplateHits      int    `json:"template_hits,omitempty"`       // 模板 expected 中 fact_hit 命中数
FactHitTop5Count  int    `json:"fact_hit_top5_count,omitempty"` // 候选扩展辅助口径
FactAlgo          string  `json:"fact_algo,omitempty"`          // v3 / v4
```

### 2.2 新增 KPIDetail 字段

```go
IsTemplateExpected bool `json:"is_template_expected,omitempty"` // 该样本 expected 为评测模板
```

### 2.3 核心函数

| 函数 | 功能 | 确定性 |
|---|---|---|
| `isTemplateExpected(expected)` | 检测 `"LLM response should ...:"` 模板前缀（含 contain/state/mention） | 纯字符串 |
| `parseFactDateSpec(expected)` | 解析日期规格（ISO / 月名日期 / 年） | 纯字符串 |
| `matchFactTemporal(got, exp, anchor)` | 用 top-1 occurred_at 作锚点，对相对时间词做确定性加减 | 日历推算 |
| `normalizeFactNumbers(s)` | 去除货币符号、千分位逗号，统一日期分隔符 | 纯字符串 |
| `matchFactShortTokens(got, exp)` | 短 expected（非中文）实义词元全部出现即命中 | 纯字符串 |
| `matchFactV4(got, exp, anchor)` | 组合：模板剔除 → 时间推理 → 数值归一 → 短词元包含 → v3 回退 | 纯字符串+日历 |
| `matchFactTop5(facts, exp, anchor)` | 主口径 miss 时在 top-5 候选内判定（短 expected 才扩展） | 同上 |

### 2.4 关键设计决策

1. **模板前缀从 `"llm response should contain"` 扩展到 `"llm response should"`**：实测存在三种模板形态——contain（49 条）/ state（40 条）/ mention（4 条）。R3-C 指出的 6 条 beam fp 中 4 条为 contain、2 条为 state，均须被剔除。
2. **时间推理锚点取 top-1 候选的 `occurred_at`**：非 ground truth，而是检索系统实际返回的记忆时间戳，与生产环境行为一致。
3. **短词元包含仅对非中文 expected 生效**：中文短 expected（如 `"武侠小说"`）词元切分语义模糊，直接返回 false 避免误配。
4. **候选扩展仅对 <15 rune 的 expected 生效**：长 expected 不进入扩展，避免引入假阳性。
5. **`-fact-v4=false` 可复现 R3-C v3 基线**：模板 expected 始终为 false（因 isTemplateExpected 返回 false），factTotal==total。

## 5. 6 条 beam fp 处理

R3-C §9.2 指出的 6 条 beam-* summarization 模板 fp，实测覆盖 3 种模板形态：

| 模板形态 | 数量 | 示例 |
|---|---|---|
| `LLM response should contain:` | 49 | `LLM response should contain: you focused on balancing...` |
| `LLM response should state:` | 40 | `LLM response should state: there is contradictory information` |
| `LLM response should mention:` | 4 | `LLM response should mention: the key point` |

**处理方式**：`isTemplateExpected` 归一化后按 `"llm response should"` 前缀匹配，全部 93 条从主 fact 口径剔除，单列统计。

R3-C 指出的 6 条 beam fp 中：
- 4 条为 `contain` 形态（已覆盖）
- 2 条为 `state` 形态（已覆盖）

**结论**：6 条 beam fp 全部消除（剔除）✅

## 9. 残留与 P8 建议

1. **`Likely yes`、`Pomodoro technique`、`Independence Day`、`a tough win`** 4 条短 expected 仍不可覆盖：got 文本中无对应信号，需 LLM 语义匹配（违反红线 4），留待 P8。
2. **5 条假阳性**中 2 条为 `fact_hit_but_top1_id_miss`（fact 文本匹配但 ID 未命中 top-1），属评测器设计特性，非算法缺陷。剩余 3 条为语义相近但非精确匹配，需 LLM 或人工标注。
3. **时间推理锚点取 top-1 occurred_at** 而非 ground truth，若 top-1 记忆时间戳错误，时间推理会误判。P8 可考虑多锚点投票或置信度阈值。
4. **短词元包含仅对非中文 expected 生效**，中文短 expected（如 `"武侠小说"`）因词元切分语义模糊被跳过。P8 可考虑中文分词器或 char n-gram 短模式。
