## 2. 根因（任务书 §C.1 原文，实测确认）

P7-D 报告 §1 脚注：公开基准 memory.fact 为 `question => answer`（LME/BEAM）或证据 turn 原文（LoCoMo），而 `expected_fact` 是纯答案，评测器按 `gotFact == expectedFact` 精确比较必然 0%。

当前实现（`eval/run_kpi.go`）：
```go
factHit := item.ExpectedFact != "" && gotFact == item.ExpectedFact
```

`res.Fused[0].Fact` 取 top-1 记忆的完整 fact 文本，与纯答案 `expected_fact` 精确相等自然 0%。**这是假阴性，非检索能力缺陷**——MRR 0.546 已证明答案被召回，仅拼接格式不同。

## 3. 改动清单

### 3.1 `eval/run_kpi.go` 主循环（line ~343）


### 3.2 新增三个纯文本辅助函数（`eval/run_kpi.go` 尾部，不调 LLM）

```go
// matchFact 判定 gotFact 是否匹配 expectedFact（忽略大小写与空白）。
// 1. 归一化后精确相等 → true
// 2. 短 expected（归一化长度 < 4，如数字/单词）→ 仅在 "=>" 后的 answer 段做边界精确匹配
// 3. 长 expected → 归一化后双向包含，且长度比 ≥ 0.3（防极短误命中）
// 4. 任一为空 → false
func matchFact(gotFact, expectedFact string) bool { ... }

// shortAnswerHit 短 expected（数字/单词）在 fact 的 answer 段内做边界匹配。
// 形如 "How many ...? => 4" 时 answer 段为 "4"，精确相等即命中；
// 若 answer 段为 "... about 4 items"，则要求 b 在 answer 段作为整词出现。
func shortAnswerHit(fact, exp string) bool { ... }

// normalizeFact 归一化：小写、去除首尾空白、压缩连续空白。
func normalizeFact(s string) string { ... }
```

### 3.3 新增 `Rank` 字段（`KPIDetail`，便于诊断）

`factHit` 只看 `Fused[0]`（top-1），本次为诊断 fact 准确率与 top-1 命中率的关系，在 `KPIDetail` 里补了 `Rank int \`json:"rank,omitempty"\``，在落盘时写入实际命中 rank。**该字段为新增只读字段，不改变现有输出、不影响 A/B/D 路口径**。

### 3.4 设计演进（v1 → v2，关键）

- **v1（首版）**：纯双向包含 + `len(b)<4` 直接拒绝。→ 公开基准 fact 25.2%。rank=1 失败 60 条里 **44 条是短 expected**（数字/单词，如 `"4"`、`"27"`、`"Tom"`），被短防护误拒。
- **v2（最终版）**：短 expected 改为「在 `=>` 后的 answer 段做整词边界匹配」。→ 公开基准 fact 32.8%，rank=1 失败降至 16 条。**rank=1 内 fact 命中率 72.8% → 92.8%**。

短答案修复原理：LME/BEAM 的 fact 是 `question => answer` 形态，短答案精确出现在 answer 段；在 answer 段做边界匹配既恢复了假阴性，又避免了与 question 里的普通词（如 "How many"）误配。

## 5. 假阳性抽查（10 条）

任务书 C.5 要求「fact 准确率 ≤ 95%，避免假阳性过松」。当前公开基准 32.8%（远低于 95%），从「fact_hit 但 ID 未中 top-1」中抽查确认假阳性是否真实。

公开基准 fact_hit 且 rank≠1：**8 条**，全部为**正确答案被误排到 rank>1**（ID 未中 top-1 但 fact 文本正确）——**属检索排序误差，不是假阳性**。示例：

| rank | expected | got（top-1 fact） |
|---|---|---|
| 2 | `7 days. 8 days (including the last day) is also acceptable.` | `How many days before ...? => 7 days. ...` |

| 2 | `3` | `How many plants ...? => 3` |
| 2 | `2` | `How many doctor's appointments ...? => 2` |

**合成集**：fact_hit 493 条中，ID 未命中但 fact_hit 为 **0 条**——**合成集零假阳性**，口径收紧未引入任何误命中。

## 6. 残余失败分析（rank=1 仍有 16 条无法匹配）

这 16 条是 **BEAM/LoCoMo 的「跨多轮推理」型**：expected 是需综合多轮对话得出的答案，而 got 是 top-1 原文 turn，文本层面本就不连续，任何包含式判定都无法覆盖。示例：

| expected | got（top-1 turn 片段） |
|---|---|
| `Toy drive, Community food drive, veterans, domestic violence` | `John: We held some events ... went to a homeless shelter to give out food ...` |
| `No, he has goals specifically in the U.S. like joining the military and running for office.` | `John: I heard some cool stories from an elderly veteran named Samuel ...` |
| `end of October 2023` | `Evan: It's a 1968 Kustom K-200A vintage guitar and I got it as a gift ...` |
| `stayed focused on recovery and worked hard to strengthen his body` | `John: Last season, I had a major challenge when I hurt my ankle ...` |

**结论**：这 16 条**不是判定过松或过紧**，而是 `expected_fact` 本身是推理产物，与任一 top-1 记忆的 fact 文本都不包含。要覆盖此类需**引入 answer 级语义匹配**（超出 C 路范围，且调 LLM 违反红线 4）。**当前 92.8% 的 rank=1 fact 命中率已接近文本口径天花板**。

## 8. 关键结论与后续建议

1. **C 路判定口径已正确**：rank=1 内 fact 命中率 92.8%，口径修正的假阴性已基本消除。公开基准 fact 32.8% 未达 50% 的**原因是 top-1 命中率仅 34.0%，属 A 路（RankFusion 英文权重重校准）的检索排序问题**。
2. **A 路必须等 C 路落地**：C 路消除 fact 假阴性后，A 路的回归评测才有可信的 fact 基线（0% → 32.8%）。建议 A 路以「top-1 命中率」为主攻指标（34.0% → 目标 ≥ 39%），MRR（0.546）与 fact 准确率（32.8%）会随之联动上升。
3. **C 路本身无需再放宽判定**：若强行把公开基准 fact 拉到 ≥ 50%，只能靠放宽判定引入假阳性，违反任务书 C.5「避免假阳性」与红线「不造假」。32.8% 是当前检索能力下的**诚实读数**。
4. **建议后续**（供用户决策，非本次实现）：
   - **A 路**：按方案 α（不引入 embedder，只调 `keyword / entity / reference_frame`）主攻 top-1 命中率。C 路已把 fact 基线修正到 32.8%，A 路可直接观测「top-1 命中率 + fact 准确率」双联动。
   - **D 路**：multi-hop 桶的 fact 36.4%（165 条中 60），结构约束与 A 路结论独立。
   - **长期**：若要覆盖 BEAM/LoCoMo 的 16 条推理型失败，需引入 answer 级语义匹配（超出 C 路，且不调 LLM 的红线限制下难以突破）。
