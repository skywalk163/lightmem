## 二、起草前的四次实测（结论直接决定 R15 怎么分）

这四条不是推测，是起草时在基线树上逐条查出来的。**其中第 3 条更正了 R14 任务书 §九.3 的书面判断，第 4 条让"北极星"退出了本轮的验收角色。**

1. **投毒防护是纯反应式的**：`kernel/writepolicy.go:241` 的 `PoisoningGuardPolicy.Validate` 首行就是 `if m.Provenance != ProvInjectionSuspect { return nil }`——它只在标签**已经**被置好时才封顶 confidence 到 0.3、截断证据片段。而 `ProvInjectionSuspect`（`kernel/model.go:33`）在全库生产代码里**只有读取点、没有写入点**（`consolidate.go:213` 与 `package_memory.go:117` 建记忆时一律写 `ProvNormal`）。即：整条防线目前**没有检测能力**。
2. **对抗样本存在但不被任何测试消费**：`eval/dataset/injection.jsonl` 只有 **20 条**，`bucket=injection` / `has_injection=true`，且 `provenance` 已在数据里**直接标为** `prompt_injection_suspect`（标签给答案，不测检测）；`grep` 全部 `*.go`，**零个引用**。`gen_holdout_proxy.go:12` 显式注释"剔除对抗样本（has_injection / has_pollution——它们是投毒测试）"，所以 holdout_v2 里 `has_injection` / `has_pollution` 均为 **0/800**。
3. **合并度分母确为 0，但缺失原因要更正**：`r13b_mergence_baseline_20261015.json` 实测 `l2_memories=0`、`memories_with_entity=0`、`entity_groups=0`、`edges_alive=0`——`mean_edges_per_memory` 分母（L2 数）为 0，`mean_memories_per_entity` 分组数为 0。逐行统计 holdout_v2 得：`layer` 全为 **L1 × 800**、`memory_kind` 全为 **fact × 800**、`reference_frame` 里 **entity 0/800、task 0/800、scene 800/800、tenant 800/800、user 800/800**。
   → **更正**：R14 任务书 §九.3 写"holdout_v2 全 L1 且无 entity / recorded_at"，其中 `recorded_at` 有误——**800/800 都有**（零时间戳 `0001-01-01T00:00:00Z` 计入），真正缺的是 `entity` 与 `task`。合并度归零的真因是**全 L1 + 无 entity 标注**，不是没有时间。
   → **连带结论**：漂移衰减三轴里**只有 scene 有标注**，entity / task 全缺失按 `Neutral=1.0` 走中性。所以"把漂移衰减接进默认链路"在 holdout_v2 上**行为零变化**——B 路的验收不能靠北极星，必须自建夹具。
4. **北极星 M1 已饱和，且 M2 的口径不能混用**：`r14_final_holdout_20261015-105651.json` 实测 `mode=holdout-official`，`m1.coverage=1`、`hits=800`、`hit_at_1_rate=1`、`mean_rr=1`、`id_hit_rate=1`，四桶全 1.0——**满分、无上升空间**。继续拿它当"验收门槛"只能证明"没坏"，证明不了"更好"。本轮验收必须换指标（§九）。
   另注意**两个北极星入口口径不同、不可混用**：`polaris_holdout.go` 产出 `mode=holdout-official`，数据面为压缩后 129537 token、`m2_control_share=0.24976978275600448`；`polaris_eval.go`（`mode=eval`）用未压缩 200295 token、`m2_control_share=0.17716630857649915`。**R14 起正式口径以 `polaris_holdout.go` 为准**，本轮所有 M2 对比一律对齐前者，不得跨入口取值。

## 四、A 路：投毒防护可评测化（优先级最高）

### A.1 依据与现状

- **文档口径**：§3.15 / §7.5 声称"抽取时对含指令性文本（如'记住以后……否则……'）降权，并标记 `provenance=prompt_injection_suspect`"；§2.6 又把 `poison_guard` 列为**不可裁剪**功能（`kernel/profile.go:321` 硬校验为 true）。
- **实现落差**（§二.1）：只有"处置"（降权 + 截断证据），没有"检测"。文档描述的是检测语义，代码实现的是处置语义——**安全核心语义在纸面上成立、在实现上是空的**。
- **可观测性现状**：`kernel/metrics.go:142` 有 `PollutionRate` 指标（`lims_pollution_rate`），但没有任何写路径会置嫌疑标签，实际恒为 0，且 `MetricsSnapshot` 里没有"检出数"这一维。

### A.2 交付物与接口

**新增** `kernel/poison_detect.go`（目标 250–380 行，纯函数为主、无全局状态、无 I/O、无随机源）：

```go
// InjectionSeverity 嫌疑强度
type InjectionSeverity int // SevNone / SevLow / SevHigh

// InjectionVerdict 单条事实的判定结果
type InjectionVerdict struct {
    Severity InjectionSeverity
    Score    float64       // ∈[0,1]，确定性打分
    Signals  []string      // 命中的规则 ID，稳定排序，供审计
    Quote    string        // 命中片段（≤ maxEvidenceChars，复用 writepolicy.go:239 既有常量）
}

// DetectInjection 确定性检测：中英文指令式模式、否定式、跨 Agent 转述式、
// 间接注入（出现在被引用内容里）、系统关键字改写变体。
// 输入只读；同输入同输出（无 map 迭代序、无 time.Now、无 rand）。
func DetectInjection(fact string, meta WriteMeta) InjectionVerdict

// MarkSuspect 把判定落成 §7.5 的既有标签与 confidence 处置，不改其他字段。
func MarkSuspect(m *Memory, v InjectionVerdict, cfg PoisonDetectConfig) bool // 返回是否实际改动
```

**`WriteMeta` 使用约束（红线 5 确定性）**：`WriteMeta` 只有三个字段——`Actor` / `Now time.Time` / `Existing *Memory`（`kernel/writepolicy.go:32`）。**检测打分只许读 `meta.Existing`**（用于"同一注入模式重复写入"的去重判定），**禁止读 `meta.Now` 与 `meta.Actor` 参与打分**（`time.Time` 的 location 参与 `==`，且引入时钟依赖）。`Signals` 必须稳定排序，禁止用 map 迭代序拼字符串。

**接入方式（关键约束）**：新增 `InjectionDetectorPolicy`，注册进 `DefaultWritePolicies()`（`kernel/writepolicy.go:126` 现有 6 条，插在 `PoisoningGuardPolicy` 之前）。**该策略对无嫌疑文本必须恒为 no-op**——由此保证既有写路径行为逐位不变、`writepolicy_test.go` 与 `server_metrics_golden_test.go` 不受影响。若接入导致任何既有测试输出变化，**不得改测试，改为由调用方显式注入该策略**。

**可选（低风险才做）**：`MetricsSnapshot` 增 `PoisonDetected int64` + `lims_poison_detected` gauge。**必须保持既有指标名与 golden 输出逐位不变**（只增行、不改行）。

## 五、B 路：把"无人调用"接上电（opt-in 接线）
