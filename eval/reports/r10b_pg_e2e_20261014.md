## 5. 性能基准（`go test -bench . -benchmem -count=1`）

```
BenchmarkPgUpsert-12          	     100	  14984454 ns/op	    3400 B/op	      33 allocs/op
BenchmarkPgQuery-12           	    2239	    528443 ns/op	   11628 B/op	     214 allocs/op
BenchmarkPgVectorSearch-12    	    2643	    454874 ns/op	   17912 B/op	     101 allocs/op
```

| Benchmark | ns/op | ms/op | allocs/op | 与内存 SQLite 对照 |
|---|---|---|---|---|
| Upsert | 14,984,454 | **15.0 ms** | 33 | 内存 map ~100 ns（快 ~150,000×） |
| Query | 528,443 | **0.53 ms** | 214 | 内存 map ~200 ns |
| VectorSearch | 454,874 | **0.45 ms** | 101 | 内存 map 不支持 |

**说明**：真实 PG 相对内存 map 有网络+磁盘开销，量级差异属预期。本路目标是验证正确性，不是性能优化。

## 6. 问题登记册（只登记不修复，修复留 R11）

| # | 严重度 | 问题 | 位置 | 描述 | 修复建议 |
|---|---|---|---|---|---|
| **P1** | **高** | **DeleteByScope SQL 语法错误** | `kernel/backend_pg.go` L624-627 | `DELETE FROM memories WHERE ... RETURNING memory_id ORDER BY memory_id ASC` —— PostgreSQL 的 `DELETE ... RETURNING` **不支持 ORDER BY 子句**，执行时报 `ERROR: syntax error at or near "ORDER" (SQLSTATE 42601)` | 去掉 `ORDER BY memory_id ASC`，在应用层对返回的 memory_id 排序；或改用子查询包装 |
| P2 | 低 | `shared_with_tenants` 列类型为 `TEXT[]`，Go 侧 `stringArrFromJSON()` 输出 `'{}'` 或 JSON 字符串——pgx stdlib 驱动是否正确编解码 PG 数组未验证 | `kernel/backend_pg.go` L151, L741-746 | TestPgUpsertGetRoundtrip 未显式断言 `SharedWithTenants` 回读 | 后续用例扩展：设置 `SharedWithTenants` 后 Get 回读对比 |
| P3 | 低 | 测试用例 Version 断言依赖首次运行——重复运行同一测试库会因 ON CONFLICT DO UPDATE 递增 Version 导致断言失败 | `eval/e2e/pg/pg_e2e_test.go` | 非生产代码 bug，是测试夹具隔离问题 | 每个用例开始前 TRUNCATE，或用唯一 tenant 前缀（带时间戳） |
