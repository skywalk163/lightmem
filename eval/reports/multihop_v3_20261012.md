## 1. 一页结论

| 数据集 | 主 MRR（口径 C，历史可比） | **口径 A MRR（top-1 ∈ Expected）** | **口径 B hit@2（top-2 命中）** | 样本数 |

| 公开基准 multi-hop | 0.960 | **0.945** | **0.982** | 165 |

**核心结论**：

1. **口径 A 落地成功**：合成集 multi-hop MRR 从恒 0.500 → **1.000**，**不再恒 0.500**（R3-D 验收核心目标达成）。150/150 条 top-1 均命中 ExpectedMemoryID。
2. **口径 A/B 双源可比**：合成集 1.000 vs 公开基准 0.945，差距 0.055。**差距来源已定位为公开基准真实检索排序问题**，而非结构约束（见 §5）。
3. **口径 A 消除了结构性惩罚**：合成集 150 条 `ExpectedMemoryID=[hop2ID,hop1ID]`（长度恒 2），主 MRR 口径对命中 hop-1 只计 0.5，口径 A 不再区分 hop 顺序。
4. **主 MRR 口径（口径 C）完整保留**：合成集仍 0.500、公开基准 0.960，与历史报告可比，不覆盖。

## 2. 背景与根因（R2 收口 §7.3 + D 路 §4）

**合成集 150 条 multi-hop 结构性下限**：
- `ExpectedMemoryID = [hop2ID, hop1ID]`（`sample.go:105 toItems`），长度恒 2。
- 评测器 `run_kpi.go:320`：top-1 命中 hop-2 → `j=0` → rank=1 → RR=1.0；命中 hop-1 → `j=1` → rank=2 → RR=0.5。
- 因此只要 top-1 召回的是 hop-1（中间跳板）而非目标 hop-2，MRR 只计 0.5——**结构性惩罚，不是检索能力缺陷**。

**公开基准 165 条 multi-hop**：`ExpectedMemoryID` 通常单元素（159/165 长度 1），top-1 命中即 rank=1，无惩罚。

**R2 D 路 §5 已提出 3 种替代口径**：A（top-1 ∈ Expected 即 hit）、B（hit@2）、C（保持现状标注下限）。R3-D 任务：**落地口径 A 为主指标，口径 B 为辅助，保留口径 C 供历史对比**。

## 3. 实现（`eval/run_kpi.go` 修改）

### 3.1 新增报告字段（KPIReport）

```go
// BucketMRRSet R3-D：multi-hop 桶「口径 A」MRR——top-1 MemoryID ∈ ExpectedMemoryID
// 即算 hit（不区分 hop 顺序），与公开基准（单元素 Expected）可比。
// 仅在 multi-hop 桶累计；不覆盖主 MRR 口径 BucketMRR（保留历史可比性）。
BucketMRRSet map[string]float64 `json:"bucket_mrr_set,omitempty"`
// BucketHit2 R3-D：multi-hop 桶「口径 B」hit@2——top-2 内任一 MemoryID ∈ ExpectedMemoryID
// 即算命中。反映「一次交互内能拿到正确事实」的体验。
BucketHit2 map[string]float64 `json:"bucket_hit2,omitempty"`
```

### 3.2 分桶统计（main 循环内）

```go
if item.Bucket == "multi-hop" && !isAdversarial {
    multiSignalTotal++
    if hit { multiSignalHits++ }
    // R3-D：口径 A（hit@1 集合判定）——top-1 MemoryID ∈ ExpectedMemoryID 即算 hit。
    multiSetTotal++
    top1ID := ""
    if len(res.Fused) > 0 { top1ID = res.Fused[0].MemoryID }
    if sliceContains(item.ExpectedMemoryID, top1ID) { multiSetHits++ }
    // R3-D：口径 B（hit@2）——top-2 内任一命中。
    if multiHit2(res.Fused, item.ExpectedMemoryID) { multiHit2Hits++ }
}
```

### 3.3 报告填充

```go
if multiSetTotal > 0 {
    report.BucketMRRSet = map[string]float64{"multi-hop": float64(multiSetHits) / float64(multiSetTotal)}
    report.BucketHit2 = map[string]float64{"multi-hop": float64(multiHit2Hits) / float64(multiSetTotal)}
}
```

### 3.5 辅助函数（纯 ID 集合判断，不调 LLM，seed 无关）

```go
// sliceContains 判断 s 中是否存在元素 target（口径 A 用）。
func sliceContains(s []string, target string) bool { ... }

// multiHit2 判断 top-2 候选内是否命中任一 ExpectedMemoryID（口径 B 用）。
func multiHit2(fused []kernel.FusedResult, expected []string) bool {
    for i := 0; i < len(fused) && i < 2; i++ {
        if sliceContains(expected, fused[i].MemoryID) { return true }
    }
    return false
}
```

## 4. 双源三口径对照表

### 4.1 合成集（multi-hop 150 条）

| top-1 rank=1 条数 | 0 | 0 | 150 | — |

### 4.2 公开基准（multi-hop 165 条）

| 指标 | R2 主 MRR | R3-D 主 MRR | R3-D 口径 A | R3-D 口径 B (hit@2) |
|---|---|---|---|---|
| multi-hop MRR | 0.923 | **0.960** | **0.945** | **0.982** |
| top-1 rank=1 条数 | — | 154 | 156 | — |
| 说明 | R2 基线 | 无回归 | 略低于 0.95 假设 | 98.2% |

### 4.3 双源可比性分析

**口径 A 下合成集 1.000 vs 公开基准 0.945，差距 0.055**。根因（逐条分析公开基准 165 条）：

| 分类 | 条数 | 解释 |
|---|---|---|
| top-1 命中 expected（口径 A hit） | **156** | 检索正确 |
| top-2 命中但 top-1 未命中 | **6** | **真实排序问题**（target 在 top-2，但被错误记忆挤到第 1） |
| top-2 内均未命中 | **3** | **真实召回失败**（expected 未进 top-2） |
| 合计 | 165 | — |

**结论**：公开基准 multi-hop 的 0.945 口径 A 反映的是**真实检索排序能力**（156/165 = 94.5% 一次交互内拿到正确事实），hit@2 98.2%（162/165）说明**绝大多数是排序而非召回缺失**。**差距是检索能力差异，不是结构约束**——这与合成集（结构约束已消除，口径 A 达 1.000）形成对比，说明合成集样本设计下检索能力已饱和。
