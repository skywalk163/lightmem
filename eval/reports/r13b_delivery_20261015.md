## 二、B.1 位移边 Schema 与存储

**文件**：`kernel/displacement_edge.go`

**边的语义**（对齐 Monty graph memory）：节点 = 记忆，**边 = displacement**——从 A 到 B 沿该关系可以预测/跳转至 B。方向固定为 `from → to`，按时间单向，避免双向重复。

**四类关系与初始权重**（枚举来源 monty.md §4.2 建议 1）：

| relation | 语义 | 初始权重 |
|---|---|---|
| `entity-alias` | 两条记忆 `entity` 归一化后相同 | 0.8 |
| `causal` | 同 user 下后条 `fact` 出现前条 entity 的指代 | 0.5 |
| `task-flow` | 挂同一 `task_id`，按时间先后 | 0.4 |
| `temporal` | `RecordedAt` 间隔 ≤ 7 天且同 task / 同 scene | 0.3 |

**`DisplacementEdge` 字段**：`from_memory_id` / `to_memory_id` / `relation` / `weight`[0,1] / `created_at`（只写一次）/ `invalidated_at`（软删时间戳，缺省 nil）。

**写入幂等**：`(from, to, relation)` 三元组为唯一键，分隔符用 `\x00` 避免与 ID 内容碰撞。三元组已存在（**无论是否已软删**）时 `AddEdge` 返回已存在行与 `false`——**不新增行、不覆盖历史权重**。

**淘汰即软删除**：`InvalidatedAt` 置非空，行仍保留在 `edges` map 中，`EdgeCount()`（审计口径，含软删）与 `AliveEdgeCount()`（有效口径）分开统计；`OutEdges` 只返回有效边，被软删的边不参与召回但保留可审计。

**建边触发规则**（`BuildEdgesHeuristic`，纯启发式、不调 LLM、确定性）：

- **只对 `Layer == L2` 的记忆建边**，L1 默认不建（与红线「只增不改默认路径」一致）。
- 按 `tenant + user` 分组后组内两两配对；按 `RecordedAt` 升序，先者为 `from`、后者为 `to`。
- `RecordedAt` 为零值的记忆不参与 `temporal` / `task-flow` 等时间类规则。
- **空实体不连边**（避免全表两两爆炸）；`causal` 用固定指代词表（它/该/这个/那个/it/its/this/that）做小写字符串匹配。

**存储形态**：本期为进程内 `EdgeStore`（`sync.Mutex` 并发安全，clock 可注入以保证测试确定性）。生产持久化（SQLite/PG 边表）留待后续轮次；接口已按「幂等写入 + 软删 + 出边查询」收敛，替换为 SQL 实现不改调用方。

## 三、B.2 多跳召回（关系式检索）

**文件**：`kernel/multihop_monty.go`

**与既有 `kernel/multihop.go` 的关系**：`multihop.go`（R4-A）是**证据式重排**——在已融合候选上按锚点覆盖度重排；本文件是**位移式召回**——从种子出发沿位移边做预测式跳转，把向量相似度捞不到、但与种子有确定关系的记忆补进候选集。**`multihop.go` 零改动。**

**`DisplacementRecall(seeds, store, accept, cfg)`** 三条显式契约：

1. **硬条件不一致即剪枝**：`accept` 是调用方传入的 §3.2 硬过滤闸门；种子 `accept=false` 直接丢弃且**不作为扩展源**，被扩展节点 `accept=false` 同样剪枝——这是「不跨越 §3.2 硬过滤边界」的唯一执行点。
2. **不累积置信度、不修改原信号分**：函数不读、不改种子的原始 `Score` / `SignalScores`，只输出边召回候选。
3. **软排序**：保留候选按 `Score = 路径权重累乘 × 0.5^hop` 排序（种子 hop0 恒为 1.0），hop 越深衰减越重；该分**只用于召回集内排序，不回灌主融合分**。

**跳数上限 N=2**：`MaxHops <= 0` 取默认 2，**`> 2` 收敛到 2 而非报错**（本期硬上限，调用方可在文档感知）。

**确定性**：BFS 按队列层序扩展；同一记忆只保留首次（hop 最小）到达；输出按 `Score` 降序、同分按 `MemoryID` 字典序全序排序。

**输出 `DisplacementCandidate`**：`memory_id` / `hop`（0=种子本身过闸）/ `score` / `path`（推理链 seed→…→本节点）/ `relation`（最后一跳所用边关系）。

## 四、B.3 容量治理与安全边界

| 约束 | 实现 |
|---|---|
| 边只用于软排序与多跳召回 | `OutEdges` 仅被 `DisplacementRecall` 消费；不参与任何硬过滤判定 |
| 不跨越 §3.2 硬过滤边界 | `accept` 闸门是唯一放行点；剪枝节点不扩展、不回溯 |
| 单记忆有效出边上限 | `DefaultMaxOutEdges = 16` |
| 超限淘汰策略 | 软删 **weight 最低、并列取 `CreatedAt` 最旧** 的有效出边 |
| 淘汰为软删除 | 置 `InvalidatedAt`，不物理删除，表中可审计 |
| 权重收敛 | `clampWeight` 将权重夹到 [0,1] |
