### 本轮修复记录（B3/B4）

- **重复 id / memory_id（初版 FAIL）**：LoCoMo 多跳题共享同一证据 turn，`RawQuestion.ID` 取 `expIDs[0]` 导致 eval 条目 id 与 memory_id 双双重复（如 `lc-conv-41-D24_3`）。已在 `sample.go` 落盘前加 `ensureUniqueIDs`：eval id 重复项追加 ` [dup#n]` 后缀（不改语义、不改 memory_id）。修复后 0 重复。
- **seed=42 非确定性（红线违例）**：`stratifiedSample` 用 `range quotas`（Go map 迭代顺序随机），不同运行下 Shuffle 序列被打乱 → all.jsonl md5 每次不同。已改为固定 `bucketOrder` 遍历（single-hop → multi-hop → temporal → open-domain），3 次运行 md5 完全一致。
- **verify 崩溃**：初版在 `dupIDs[:5]` 打印示例时对切片越界 panic（重复 id 仅 1 个）。已加 `trimList` 安全截断。
- **verify 语义修正**：memory_id 跨条目复用是 LoCoMo 多跳合法形态，降为 `[1b]` 提示项，不参与硬判 FAIL；补齐 `ExpectedFact` 完整性检查。

## 9. 字段映射与已知边界

- memory.fact：LongMemEval / BEAM 用确定性模板 `question => answer`（官方原文拼接，非 LLM，600/650）；LoCoMo 直接取证据 turn 原文（50/650）。
- kernel Schema 字段：`reference_frame.{tenant,user,scene}` 650/650、`source_evidence.{origin,snippet}` 650/650、`visibility=tenant`、`layer=L1`、`provenance=normal`、`confidence=0.9`。
- `recorded_at`/`occurred_at`：LME 500/500（`question_date`）、LoCoMo 50/50（session `date_time`）共 550/650 有效；BEAM 源数据无时间字段，留零值（不引入 `time.Now()`，保持确定性）。
- 双时态 `valid_from/valid_until` 未填：三基准均无"知识过期/变更"标注字段，仅靠 `is_temporal` 与 `occurred_at` 支持时序回溯；P7-D 若需变更样本可后续补标。
- **memory_kind 当前全为 `fact`（650/650）**：`bench/helpers.go::newMemory` 硬编码 `kernel.KindFact`。任务书 §3.3 要求按内容类型推断（preference / procedure / event），但该字段属 B1 适配器职责（已由协作方交付），本轮 B3/B4 未改动它。若下游 KPI 需要 kind 区分，可在 `newMemory` 增加规则推断（纯规则、不调 LLM），不影响已落盘数据可复现性。建议作为 P7-D 前置微调项。
