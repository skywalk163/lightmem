## 路 5 — 光明语言语法能力补齐（L-075~L-078）【语言升级 P1 · lexer/parser/runtime】

> E5（lightharness 令牌计量 + 压缩）实测踩到的 4 条语言缺陷，**已登记 `docs/功能对标/语言缺陷账.md` L-075~L-078**。目前 0.88 失败列表未直接暴露（这些失败集中在 stdlib 测试），但 lightharness 复刻已因此被迫绕行，是光明升级的头号驱动项。本路根治后，lightharness 可去掉绕法。

**涉及层**：`src/lexer.py` / `src/parser_core.py` / `src/code_generator*.py` / `src/llvm/codegen_typed.py` / `stdlib/*.light`

**逐项任务**
- **L-075 不支持 hex 字面量**（`0x4E00` 语法错误）
  - 期望：lexer 识别 `0x` 前缀十六进制整数字面量，值等同十进制。
  - 绕法：Unicode 码点用十进制 + 注释标 hex。
  - 修法：lexer 数字识别加 `0x[0-9a-fA-F]+` 分支，parser 生成整型字面量；补最小复现 `段 主: 设 码 为 0x4E00; 输出(码)`。
- **L-076 `空` 是保留字，不可作变量名，报错不明确**
  - 期望：`空` 作变量名时给**明确**报错（如"空 是关键字，不能作变量名，请用 空内容/空值/占位"），或评估放开为可用变量名（需权衡 `空` 作为 None 字面量的语义）。
  - 关联：路 3 里 `无→空` 改名正是同一根因的测试侧缓解；本路根治。
  - 修法：parser 变量声明处对保留字做友好报错；若要放开，需确保 `空` 字面量语义不受影响。
- **L-077 列表无 `.移除()`/`.弹栈()`，只有 `.弹出(i)`**
  - 期望：列表补 `移除(值)`（按值删，内部找索引再 `弹出`）与 `弹栈()`（=`弹出(长(列表)-1)` 或栈语义）。
  - 绕法：按值删先找索引再弹出；清空用循环 `弹出(0)`。
  - 修法：在列表 builtin / runtime 补这 2 个方法（native + 解释器双后端对齐）；补复现测试。
- **L-078 不支持闭包 / 嵌套函数（最大项，建议分阶段）**
  - 期望：支持嵌套函数定义 + 闭包捕获外层变量，有状态回调可用嵌套函数而非 "类 + bound method"。
  - 绕法：定义类持有状态，方法作 bound method 传入；钩子返回值被忽略时原地改参数。
  - 修法（设计项）：需在 codegen 引入词法作用域环境（closure env），native 后端改动最大。**建议本路先做 L-075/076/077（增量、低风险），L-078 做可行性设计 + 最小原型，方案与 language owner 对齐后再全量实现**；未实现前 lightharness 维持"类 + bound method"绕法。

**交付要求**
- 每条在 `docs/功能对标/语言缺陷账.md` 的 L-075~L-078 条目补充"修复状态/PR 链接"。
- 为每条补最小复现 `.light` 测试（放 `tests/` 对应用例或 `examples/`），确保修完有回归保护。
- 双后端（解释器 + 原生 LLVM）必须都验证通过。

**验收**：本地 `python -m pytest` 对应复现用例绿 + 0.88 确认；lightharness 侧能删掉 L-075~L-077 绕法（L-078 视设计进度）。
