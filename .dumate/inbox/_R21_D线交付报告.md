### 4.1 实跑踩到的三个坑（都已修进脚本，并写进 README）

1. **执行策略**：本机 `Restricted`，`.\gen_configs.ps1` 直接被拒（`UnauthorizedAccess`）→ 文档改为
   `powershell -NoProfile -ExecutionPolicy Bypass -File`。
2. **脚本编码**：UTF-8 **无 BOM** 的 `.ps1` 在 PS 5.1 下按 GBK 解析，中文注释把字符串引号吃掉，
   报「哈希文本不完整」等一堆语法错 → 脚本必须带 BOM（与 JSON 必须无 BOM **相反**，两条都已写入 README 陷阱⑥）。
3. **JSON 转义**：Windows 路径 `C:\Python314\python.exe` 原样替换进 JSON，`\P` 是非法转义，解析器报
   `无法识别的转义序列` → 生成器对 JSON 模板做 `\`→`\\`、`"`→`\"` 转义后才替换。

### 4.2 设计取舍

- **模板即文档**：模板用 `<YOUR_TOKEN>` 等占位符，既可整段粘贴，又能被生成器做纯文本替换（不引入模板引擎）。
- **只产出待粘贴副本**：生成器写 `-OutDir`（默认 `./out`），并对 6 个 Agent 配置目录设了硬护栏；避免误伤既有配置（如 WorkBuddy 的 `lighthouse-ops`/`agentsync`、Box-Agent 的托管 `mcp.system.json`）。
- **每份产物附 `MANIFEST.md`**：生成文件 → 目标绝对路径 → 粘贴方式（追加/合并/整文件），省掉查表。
- **身份按 agent 区分 token**：`TokenKey` 与模板解耦（`trae-workspace` 复用 `trae` 的 token，`codearts-bridge` 复用 `codearts`）。

## 5. 跨线发现与待裁决（**请合流者优先看本节**）

| # | 发现 | 证据 | 影响 | 建议归属 |
|---|---|---|---|---|
| **D-1** | **stdio 通道的身份传递未定义**。§3.1 只规定 `Authorization: Bearer`（HTTP 头）；stdio 无请求头 | 任务书 §3.1；`configs/codearts.mcp_settings.json`、`roo-cline.mcp_settings.json` 只能留空 `env` | 多个 Agent 共用一个 `lightmem-mcp -transport stdio` 进程/二进制时，服务端无法区分谁在写；`agent_id` 会全落成同一个 | **B 线**：约定进程环境 `LIMS_AGENT_TOKEN`（单值）或 `-agent-token` flag，并在 `auth.go` 读取 |
| **D-2** | **`goal/state` 入参名不一致**：冻结 `status`，实现 `state` | `kernel/router_tools.go:278` → `State GoalState \`json:"state"\``；任务书 §3.2 写的是 `status` | A 线按冻结口径写 schema → Agent 传 `status` 返回 200 但**状态不变**（静默无效，最难查的一类） | **C 线**改实现或**A 线**改 schema，二者必须选一；建议实现兼容两种键 |
| **D-3** | **token 表需扩到 8 家**：冻结表只有 6 家 | §3.1 表 vs §3 本目录覆盖 8 家 | `trae-solo`、`roo-cline` 没有 token 就落不到身份，`private` 可见性判断也缺依据 | **B 线**补两条；部署侧 `LIMS_AGENT_TOKENS` 同步 |
| **D-4** | **Python 桥不发认证头** | `lightmem_mcp_bridge.py:123` 只有 `Accept`，无 `Authorization`；`http_json` 未注入 | 一旦 18443 开 `LIMS_REQUIRE_AUTH=1`，CodeArts / Roo 的桥通道**立刻 401**，而这两家恰好是「只能 stdio」的 | **E 线**（桥属过渡通道）或 B 线给桥加 header |
| **D-5** | **Windows 侧没有 `lightmem-mcp` 二进制**（红线⑤不安排 Windows） | 本机无 Go、未构建 | CodeArts（Windows IDE）与 Roo（Windows VSCode）**无法用原生 stdio**，只能用桥 | 已在文档中双模板并存；根治要等这两家支持 HTTP，或把 IDE 迁到 Linux |
