### 实现要点

- **点 ID 契约修复（真机暴露）**：Qdrant 1.19 的 `ExtendedPointId` 只接受 u64 整数或 UUID 字符串，lightmem 的 MemoryID 是 29 位十六进制 ULID 风格字符串，直接透传被真机全部 400 拒绝。`qdrantPointID` 用 UUIDv5 风格（namespace `lightmem-qdrant1` + SHA-1 取前 128 位）确定性映射，原 MemoryID 完整保留在 payload._memory 中，对外语义不变。R16 的 httptest mock 接受任意字符串 ID，**掩盖了该契约差异**（mock 保真度问题，见 §5）。
- **读己之写**：Qdrant 写为异步两段提交（acknowledged→completed），写路径统一 `?wait=true`。
- **向量保留**：Upsert 前 fetchPoint 探针，点已存在且向量完整时沿用旧向量，防零向量覆盖。
- **真机测试门控口径**（与门禁 [11] PG 一致）：`LIGHTMEM_QDRANT_HOST` 未配置 → 3 个真机用例显式 `t.Skip`；已配置 → 任何失败即 FAIL。`TestQdrantRealConfigGate` 无 env 依赖，随常规测试跑，守护门控判据本身。
- **部署脚本**：纯 POSIX sh，ZFS dataset → jail 基座 → jail.conf → epair/bridge → 出网三件套 → pkg → 配置/启动 → pf 放行 + 健康检查；每步先查后做；pf 改写前必做 `pfctl -nf` 语法校验（防锁死 SSH）；`--verify` 只读模式。

## 3. 真机网络拓扑发现（本泳道新增知识，已写入 §11A.6.4 与 pf.rules 注释）

1. **工作站是宿主机 VirtualBox 内的 VM**（10.0.2.15，用户态 NAT）：VM 访问“宿主机自身 IP”被 NAT **回环为 lo0 流量**（源/目的均为 192.168.0.88），完全不经 em0——宿主机 pf/rdr 对其不生效（tcpdump em0 零包证实）。**正确访问路径 = jail IP 10.0.10.60 直连**。
2. **lo0 rdr 已回退**：前向翻译成功但反向翻译/状态回写失败（宿主机对 jail 的 SYN-ACK 回 RST，curl exit 28）——FreeBSD pf 对本地产生流量的已知局限。
3. **Gitea（192.168.1.5）无到 192.168.0.0/24 的路由**（包经 192.168.1.1 漏互联网），不能作 rdr 外部测试客户端；规则保留 192.168.1.0/24 源网段备用。
4. **192.168.0.0/24 段内其他活主机**（.12/.13/.82/.86/.101/.103/.104/.105/.109 等）无 workbuddy 密钥，不能代为验证。
5. **pf 计数器噪音**：rdr/pass 规则上百次 evaluations 来自互联网 22 端口扫描（em0 分钟级十万级包），非真实 6333 客户端。

## 6. 真机实测入测的两个 Qdrant 1.19 语义

1. **Cosine 集合落库归一化向量**：预置首分量 0.647 读回 0.03493356（≈0.647/18.5，即 /|v|）。“向量保留”断言必须按**方向保持**（读回与预置余弦相似度 ≈ 1），逐分量比对必失败——已写入测试与 §11A.6.3 #8。
2. **GET 单点默认返回 vector**（无需 `with_vector=true`），len=1024；同时确认 backend Upsert 按契约只写零向量（VectorStatus=pending），向量由 embedder 补全——真机测试的 VectorSearch 路径一据此模拟 embedder 落库后再检索，避免依赖零向量在 Cosine 下的未定义行为。
