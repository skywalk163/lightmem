## 二、关键设计对齐任务书

| 任务书要求 | 实现方式 | 真机证据 |
|---|---|---|
| **纯 stdlib**（红线⑦） | A 线所有 `.go` 仅引 `net/http` + `encoding/json` + `bufio` 等标准库 | `go.mod`/`go.sum` 零变化（红线 diff 核对通过） |
| **双传输** | `stdio`（`bufio.Scanner` 大缓冲，UTF-8，禁 GBK）+ `streamable-http`（`/mcp` 三方法，SSE 与 JSON 协商） | HTTP 19544 握手 + stdio 管道握手均通过 |
| **A/C 解耦**（§十） | 13 工具一律 `mcpRESTClient.do` 走 loopback HTTP，**不 import C 线新函数** | A 线编译不依赖 C 线签名 |
| **挂 B 线鉴权** | `main.go` 调 `kernel.LoadAgentTokens` + `AuthMiddleware`；未配置 token 时按红线④透传 | 日志 `[auth] ... 透传（R21-B 默认关）` |
| **G3 清零** | `goal_create` schema 显式含 `goal_detail`；handler 透传 `goal_detail` 至 REST | 带 `goal_detail` → 201；缺 → 422 被拒 |
| **G5 清零** | 6 个工作流工具入参均支持 `tenant_id`/`user_id` 并透传（不硬编码 `default`） | 不同 tenant 建计划互不可见 |
| **G6 清零** | `plan_list` 工具 + C 线 `GET /tools/memory/plan` 端点打通 | 列计划返回该租户计划列表 |

## 四、遗留缺陷与降级说明

| # | 现象 | 根因 | 责任线 | 影响 |
|---|---|---|---|---|
| **L-A1** | `plan_list` 输出的 `progress=`/`status=` 为空 | C 线 `GET /tools/memory/plan` 返回 `[]QueryResult`（不含 `goal_detail`）；A 线受任务书"§3.2 冻结接口"与"文件域不相交"约束，**不得越线新增端点或直接 import C 线函数** | **C 线** | 任务书验收"列计划看到 progress=0.5"的文字级呈现未达成；链路本身成功（`goal_progress` 已确认写回 progress=0.5） |

**降级处理**：A 线在 `plan_list` 输出中保留 `progress=`/`status=` 占位，一旦 C 线在 plan 响应中补 `goal_detail` 即可直接显示，A 线无需改动。**本项不阻塞 A 线交付**，因为 A 线职责是把 C 线 REST 包成 MCP tool，数据形状由 C 线决定（§十 A 线解耦约定）。
