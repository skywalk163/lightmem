> 概念已多源核实（原书 + 科普中国书评 + Closer to Truth 讲座）：新皮质约 **15 万根皮质柱**，每根附着**同一事物的多个参考系**、性质组织在参考系之中；柱间**投票**达成共识（解决绑定问题），**分歧即不确定**；**思考=在参考系中运动**，学习靠运动（传感-运动闭环）；智能四属性=**连续学习（不从零重训练）/ 靠运动学习 / 多模型冗余 / 参考系组织知识**；旧脑（本能层）与新脑（学习层）分离；预测误差驱动注意。

| # | 千脑概念 | lightmem 现状（8db1b78） | 差距 | 落地 |
|---|---|---|---|---|
| 1 | 皮质柱各自达成完整解释，**投票涌现共识** | 8 路信号加权和（RRF）+ `VoteFusion`（对多版本候选做**信号分加权平均**） | 无「解释级共识投票」——单路信号（ref）正确也被加权和稀释（P3 根因） | **A** |
| 2 | **分歧=不确定**（预测误差驱动注意） | `LowConfidence`=top1 低于绝对地板的**阈值**判定；`RequiresConfirmation`=接近平局 | 置信度不来自信号间分歧，无法预测「这题可能要答错」 | **A** |
| 3 | **参考系是知识的组织核心**（一物多帧） | `ReferenceFrame` 单帧 4 坐标（entity/project/scene/task），作为 8 路信号之一且权重 0.0 | 单帧；无帧间变换/多帧匹配；信号有效却无话语权（P3） | **A** |
| 4 | **思考=在参考系中运动**（多视图探测） | 单发 query 检索 | 无查询「运动」/多视图集成；改写 query 若用 LLM 违反红线，必须确定性模板 | **D** |
| 5 | **连续学习**（永不停止更新、不从零重训练） | `Consolidator`（去重/采纳）已实现 | 无「稳定性-可塑性」量化：增量写入后旧集召回保持率未测 | **B** |
| 6 | **组合物体**（物体=子物体，各有参考系） | multi-hop 是**检索期** hop 链（`multihop.go`） | 无**存储期**组合记忆（记忆引用子记忆、子帧继承/覆盖） | **B** |
| 7 | **多模型冗余=优雅降级** | 多信号融合 | 无消融鲁棒性度量（关一路信号检索是否存活） | **D** |
| 8 | 旧脑/新脑分层（本能层 vs 学习层） | `WritePolicy`（投毒/注入防御）vs 学习记忆 | 已对齐，本轮不动，登记备查 | — |

**一句话结论**：lightmem 已自发收敛到千脑理论的「参考系 + 多信号 + 巩固」三根支柱，缺的是**投票共识（解释级）**、**运动（多视图）**、**冗余可测（消融）**、**连续学习可测（retention）**、**存储期组合**五块——这正是 R6 四路的理论出发点。

## 1. A 路 — 千脑投票共识 + 参考系深化（P3 突破）

### A.0 范围与红线澄清

- **允许**：新增 `kernel/voting.go`（解释级共识投票 + 分歧置信度）；改 `kernel/rank_fusion.go`（新增投票融合模式，flag 门控默认关闭保不回归）；`ReferenceFrame` 多帧**新增**（`ReferenceFrames []ReferenceFrame` 可选字段 + 帧变换匹配，只增不改）；新增 `eval/polaris/polaris_voting.go`。
- **禁止**：改 `Memory`/`RouterContext`/`RecalledCandidate` 既有字段语义；投票模式默认开启（必须 rrf 默认）；用 LLM 做任何查询改写。
- **前置**：R5-A 已明确「ref 权重纳入无收益」（加权和口径）；本路换**共识投票**口径再战 P3。现有 `VoteFusion`（rank_fusion.go:287）是信号分加权平均，**不是**柱间投票，不要改它的语义，新写一条通路。

### A.1 背景（根因）

P3：ref 信号在 60 条校准集 `expected_ref_top1=1.0`（100% 区分度），但融合 top-1 命中 0.0——加权和下 ref 的 0.1 权重（即使抬到 0.1）被 semantic=12/keyword=3.2/entity=2.9 稀释。千脑答案：每根「柱」（每路信号/每个检索层）应各自达成**解释**（top-K 排名），再按解释投票——正确解释拿多数票即胜出，且**票数分布直接给出分歧度**。

### A.2 交付

1. **`kernel/voting.go`（新增）**：
   - `Interpretation`：单路信号/单层产出的 top-K 解释（候选 ID 序列）。
   - `ConsensusVoter`：对 N 路解释做**秩投票**（倒数秩计票，确定性；不得引入随机平局打破——固定按 signal 名次序），输出共识序 + `Consensus`（头部候选得票率）+ `Divergence`（1−Consensus）。
   - `Divergence` 接入融合结果：FusedResult **新增可选字段**（只增不改）或 side-channel 结构，供上层做「分歧大→低置信/需确认」判定。
   - 参考系多帧：`ReferenceFrames []ReferenceFrame`（可选）+ 帧变换匹配（查询帧与任一副帧匹配即得分，取代单帧 dilution）。
2. **`kernel/rank_fusion.go`（修改）**：新增融合模式 `vote`（`-fusion vote|rrf`，**默认 rrf**）；投票模式下各信号的 top-K 解释按 A.2.1 计票；保留 rrf 全路径逐位不变（isolate 复现）。
3. **`eval/polaris/polaris_voting.go`（新增）**：投票口径评测——ref 桶 + 全桶 + 公开/合成不回归 + 分歧度与 top-1 错误率相关性（Spearman 或分箱，确定性实现）。
4. **报告**：`eval/reports/voting_consensus_reframe_<ts>.md`：投票设计、ref 桶前后对比、分歧度-错误相关性、双源 MRR 不回归对照。

### A.3 命令（0.88 上执行）

```sh
cd /tmp/duan-light-merge/lightmem

# 投票模式：ref 桶
go run ./eval/polaris/ -holdout eval/dataset/holdout_proxy.jsonl -fusion vote \
  -report r6a_vote_ref
# isolate：rrf 复现基线（逐位一致）
go run ./eval/polaris/ -holdout eval/dataset/holdout_proxy.jsonl -fusion rrf \
  -report r6a_rrf_base
```

### A.4 验收

- ref 桶 M1 覆盖率 **≥ 0.85**（现 0.667），且 single-hop/multi-hop/open-domain/temporal 各桶降幅 ≤ 0.5pp。
- 投票模式公开/合成 MRR 不回归（≤ 基线 −0.002）。
- 分歧度与 top-1 错误率**正相关可测**（报告给曲线/表格）。
- `gofmt -l` 无输出；`go vet ./...` + `go test ./...` 全绿（root + kernel 两模块）。

## 2. B 路 — 连续学习（retention）+ 组合记忆

### B.0 范围与红线澄清

- **允许**：新增 `kernel/composition.go`（组合记忆）；改 `kernel/consolidate.go`（巩固器接组合语义，既有测试不回归）；新增 `eval/polaris/polaris_learning.go`（retention 评测）。
- **禁止**：改 Memory 既有字段语义（组合用**新增可选字段** `components`）；用 LLM 生成增量语料（增量记忆用确定性模板生成）。
- **前置**：`Consolidator` 已实现去重/采纳；`multihop.go` 是检索期 hop 链，本路建**存储期**组合（父记忆引用子记忆 ID，检索时展开）。

### B.1 背景（千脑「连续学习」+「组合物体」）

连续学习四属性之一：模型永不停止更新、不从零重训练。lightmem 的写入是增量自然的，但**没有度量**：写入 1000 条新记忆后，旧基准集召回是否保持？组合结构：皮质柱对「物体=子物体各自成帧」建模；lightmem 的多跳是检索时顺链，缺存储时组合（如「会议纪要」记忆由 3 条子事实组合而成，子事实各有参考系）。

### B.2 交付

1. **`eval/polaris/polaris_learning.go`（新增）**：
   - 基准集 M1（holdout_proxy）→ 增量写入 N=100/300/1000 条确定性模板新记忆（seed=42）→ 复跑基准集 M1 = **retention(N)**；输出曲线 JSON + 摘要。
   - 同时测新记忆可检索性（可塑性）：增量集自身 M1。
2. **`kernel/composition.go`（新增）**：
   - Memory **新增可选字段** `components []string`（子记忆 ID；只增不改）。
   - `Compose(parent *Memory, children []*Memory)` / `Decompose`：组合/拆解；子记忆参考系**继承 + 覆盖**规则（确定性）。
   - 检索集成：`RecallAndFuse` 对组合记忆按需展开（flag `-compose-expand`，默认开；关时 isolate 复现）。
3. **`kernel/consolidate.go`（修改）**：巩固器的去重/采纳规则感知 `components`（组合不去重拆散；子记忆被采纳时父记忆组件列表同步更新——确定性）。
4. **报告**：`eval/reports/continuous_learning_composition_<ts>.md`：retention 曲线、组合记忆设计与对拍、consolidate 回归对照。

### B.3 验收

- **retention(N=1000) ≥ 0.95**（相对增量前基准集 M1）。
- 组合记忆：存取-展开-检索对拍单测全绿；`consolidate` 既有测试不回归。
- 公开/合成 MRR 不回归（组合展开默认开启时 ≤ 基线 −0.002）。
- `gofmt -l` 无输出；两模块 `go vet` + `go test` 全绿。

## 4. D 路 — 评测有效性 + 多视图主动感知 + 冗余鲁棒性（P9）

### D.0 范围与红线澄清

- **允许**：改 `eval/polaris/polaris_eval.go`（**本轮唯一改此文件的线**，新增 `-validity` / `-no-anchor` / `-ablate` / `-multiview` 开关）；新增 `eval/polaris/polaris_validity.go`。
- **禁止**：改 kernel；用 LLM 做查询改写（多视图必须是确定性模板：同义模板替换、括号锚剥离、语序变体）；为刷指标改判定口径。
- **前置**：P9——重构数据集 query 括号是消歧锚（50 组×周一/周二/周三互斥事实的设计，生成器 line 73 注释），含答案 token；需无锚变体量化「锚红利」。

### D.1 背景（千脑「思考=运动」+「多模型冗余」）

运动：回忆=在参考系中移动——对同一意图用多个确定性「视图」（模板变体）探测，集成结果应≥单视图。冗余：15 万根柱冗余=关掉一些仍能识别——逐路消融信号，MRR 应优雅降级（任何单路关闭降幅 ≤5pp）。

### D.2 交付

1. **`eval/polaris/polaris_validity.go`（新增）**：
   - **无锚变体**：确定性剥离 query 括号锚（`（...）` 尾缀）生成变体集，对照「锚 vs 无锚」MRR/M1，量化锚红利（预期 single-hop 无锚 MRR 明显低于 1.0——那是**真检索难度**）。
   - **消融鲁棒性**：逐路关闭 8 信号之一（`-ablate <signal>`），输出 MRR 保持率曲线（JSON + 表）。
   - **多视图集成**：每 query 生成 3–5 个确定性模板视图（如「X的Y是什么」/「X 的 Y 是啥」/「查 X 的 Y」/语序变体），分别检索后按候选得票集成，对照单视图 M1。
2. **`eval/polaris/polaris_eval.go`（修改）**：接上述开关；明细记录所用视图/消融配置（报告 config 段）。
