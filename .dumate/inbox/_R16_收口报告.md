## 一、S1 Qdrant 后端（骨架实现）

### 1.1 设计要点

- **stdlib-only**：只用 `net/http` + `encoding/json`，**不改 `go.mod`**（R16 S1 红线）。
- **只增不改**：`StorageBackend` / `LayerScanner` / `ComplianceBackend` 三接口全实现，`model.go` / `storage.go` / `lifecycle.go` / `compliance.go` **未改**。
- **未配置即报错**：`cfg.Qdrant == nil` 或 `Host == ""` 时返回明确 error，不静默降级（延续 R15「SKIP 不冒充 PASS」口径）。
- **确定性打分**：文本检索 `Query` 用 `tokenize` 词元重合度，与 SQLite/PG 骨架行为一致，保证 `eval/run_kpi.go` 在 qdrant 档位可复现。
- **幂等建集合**：`ensureCollection` 先 GET 探测，404 后 PUT CREATE（仅 DDL CREATE，符合 R14 红线）。
- **VectorSearch 降级**：向量缺失或搜索失败时降级为 `Query`（§4.2 约定）。

### 1.2 接口实现清单（20 项方法）

| 接口 | 方法 | 说明 |
|---|---|---|
| `StorageBackend` | `Name / Ping / Upsert / Get / Query / VectorSearch / CountByKind / Close` | 主接口 8 项 |
| `LayerScanner` | `ScanLayer / UpdateLayer` | 温度分层 |
| `ComplianceBackend` | `ExportByScope / DeleteByScope / DeleteByID` | GDPR/被遗忘权 |
| 内部工具 | `do / ensureCollection / memoryPayload / parseMemoryPayload / fetchPoint / scrollAll` | HTTP 底层与 payload 序列化 |

### 1.3 接线（`kernel/profile.go`）

## 二、S2 节点角色与拓扑（骨架）

### 2.1 `kernel/node_role.go`

- **四类角色**：`RoleCoordinator / RoleWorker / RoleArchive / RoleGateway`（§5.4 对齐 NetworkConfig.Roles）。
- **接口骨架**：`PreFilter`（跨节点粗滤）、`NodeRegistry`（注册/心跳/PurgeStale）、`CrossNodeBroadcaster`（撤销广播）。
- **内存实现**：`InMemoryNodeRegistry`（RWMutex + map）、`InMemoryBroadcaster`（订阅/取消/Revoke 扇出）。
- **拓扑装配**：`BuildTopology` 从 `NetworkConfig.Roles` + `ScalingConfig.Nodes` 构建 `[]*NodeInfo`（默认不进入主线）。

### 2.2 `kernel/topology.go`

- `Topology`：`AddNode / RemoveNode / Connect / Get / All / Edges` + `recomputeLocked`（BFS 从 root 重算 hop + Parent）。
- `RevocationStore`：`Add / Has / PurgeExpired / All`，TTL=0 表示永久，过期自清。
- **接线默认关**：`CrossNodeRankMerge` 由 `profile.features` 控制，默认不进主线（R16 红线④）。

### 2.3 单测（`node_role_test.go` + `topology_test.go`）

- 注册/心跳/PurgeStale/广播（全局 vs 具体租户）/Unregister 错误路径。
- Topology 节点增删、hop 重算、RemoveNode 孤儿挂 root。

## 七、S7 ZFS 快照容灾

### 7.1 脚本 `scripts/zfs_backup.sh`（298 行，纯 POSIX sh）

子命令：`snapshot / prune / send / all / list / rollback`。
选项：`-p POOL/DS`、`-r` 递归、`-t hourly|daily|weekly`、`-k N` 保留数、`-d DEST`、`-s DS@SNAP`、`-n` dry-run。
退出码：0 成功 / 1 运行期失败 / 2 参数错误 / 3 环境缺失。

设计要点：① 只删本脚本命名规范快照（`@<TYPE>-*`）；② 幂等（同时间戳 SKIP）；③ 增量发送（有共同快照用 `-i`）；④ 确定性命名；⑤ 递归映射；⑥ ssh 加 `BatchMode` / `ConnectTimeout`。

### 7.2 手册 §10（+255 行）

覆盖快照策略与保留窗口、各子命令示例、crontab 三档定时、`zfs send` 异地/本地容灾、rollback 恢复演练、故障排查。
