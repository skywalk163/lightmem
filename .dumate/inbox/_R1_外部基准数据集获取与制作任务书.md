## 1. 三个基准的官方口径

> 以下口径以公开资料为准，**子集规模以"官方原始数据集"为基础**，本轮只做子集抽取 + 格式适配，不做内容改写。

| 基准 | 提出方 / 会议 | 评测目标 | 核心形态 | 本轮子集规模 |
|---|---|---|---|---|
| **LongMemEval** | ICML 2025（长对话长期记忆基准） | 长对话中长期记忆能力，含信息提取、时间推理、知识更新等 | 对话历史 + 问题集，提供多个变体数据集 | **约 500 条 query**（原数据集多变体，本轮取主变体子集） |
| **LoCoMo** | Snap Research / ACL 2024 | 长多轮对话中信息存储与检索，含单跳/多跳问题 | 10 组长对话 + 多跳 QA | **10 组对话 ≈ 50 条 query**（多跳为主） |
| **BEAM** | Mem0（2025） | Agent 记忆良性评估（benign evaluation），衡量记忆系统对 agent 任务的支撑 | 任务型对话 + 可验证事实问题 | **约 100 条 query**（benign 子集） |

**合计目标：≥ 650 条 query**，覆盖单跳、多跳、时序、开放域四类能力，与既有 `eval/dataset/`（570 条合成样本）形成"合成 + 公开"双源评测，满足 P7-D 公开基准对标需求。

> **红线确认**：上述三个基准的原始数据为**第三方公开数据集**。获取 = 拉取官方原始数据；制作 = **仅做格式适配与子集抽取**（转换到 LIMS 统一 Schema、对齐字段、固定 seed 采样）。**禁止**用 LLM 生成/改写 query 或 expected 答案。

## 3. B1 基准适配器

### 3.1 目标

把三个公开基准的原始格式统一转换为 `lightmem/kernel/model.go` 的 `Memory` Schema 单真源字段，供下游评测器 `run_kpi.go` 复用（复用现有评测链路，不新造一套）。

### 3.2 接口

```go
// lightmem/eval/benchmarks/adapter.go
type BenchmarkSource string // "longmemeval" | "locomo" | "beam"

type RawConversation struct {
    ID        string
    Turns     []RawTurn
    Questions []RawQuestion
}
type RawTurn struct {
    Speaker string
    Text    string
    Ts      string // RFC3339
}
type RawQuestion struct {
    ID        string
    Query     string
    Expected  []string // expected fact(s)
    Bucket    string   // single-hop | multi-hop | temporal | open-domain
    AsOf      string   // 可选，时序用
}

type Adapter interface {
    Source() BenchmarkSource
    Parse(rawPath string) ([]RawConversation, error)
    ToMemories(raw RawConversation) []Memory     // 转换为 kernel.Memory
    ToQuestions(raw RawConversation) []RawQuestion // 转换为 query 集
}
```

三个适配器 `LongMemEvalAdapter` / `LoCoMoAdapter` / `BeamAdapter` 分别实现上述接口。

### 3.3 字段映射（对齐 §4.1 单一真源）

| 目标字段（LIMS Schema） | 来源 | 说明 |
|---|---|---|
| `memory_id` | 原始 id + 基准前缀（`lme-`/`lc-`/`beam-`） | 保证跨基准不冲突 |
| `memory_kind` | 内容类型推断（fact / event / preference / procedure） | 规则推断，不调 LLM |
| `fact` | 对话中的可验证事实 | 抽取自 turn 文本 |
| `tenant_id` / `user_id` | 基准固定值 `t-lme` / `u-lme` 等 | 统一基准租户 |
| `reference_frame` | entity / scene / task | 规则抽取实体名 |
| `recorded_at` / `occurred_at` | turn 时间戳 | 时序桶依赖 |
| `valid_from` / `valid_until` | 双时态 | 变更样本标注 |
| `confidence` | 固定 0.9 | 公开基准视为高置信 |
| `source_evidence` | 原文片段 | 溯源 |
| `provenance` | `normal` | 非对抗 |

### 3.4 分桶标注

- **single-hop**：一条 fact 即可回答（LoCoMo 单跳、BEAM 部分）
- **multi-hop**：需 2+ fact 链式（LoCoMo 多跳、LongMemEval 部分）
- **temporal**：需 `as_of` 回溯 / 双时态（LongMemEval 时间推理子集）
- **open-domain**：开放域（BEAM benign、LongMemEval 部分）

## 4. B2 子集抽取与确定性处理

### 4.1 固定 seed 确定性

- 固定 seed = **42**（与既有 `eval/dataset/` 一致，保证可复现）。
- 采样算法用 `math/rand` + `seed=42`，**确定性输出**，禁止随机抖动。
- 子集规模见 §1 表格：LongMemEval ≈ 500、LoCoMo ≈ 50、BEAM ≈ 100，合计 ≥ 650。

### 4.2 唯一性保证

- `query` 文本两两唯一（复用 R138-B v2 的教训：同 query 对应多 expected 会结构性封顶准确率）。
- 若原始 query 有重复，追加区分后缀（如基准前缀 + 序号），**不改写语义**。

### 4.3 红线

- **禁止 LLM 参与**：不生成、不改写、不总结任何 query 或 expected 答案。
- 只做：格式转换、子集采样、字段映射、分桶标注、去重。
