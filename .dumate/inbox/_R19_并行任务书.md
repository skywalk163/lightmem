## 一、背景与根因（均为 R160 实测证据）

### I-12 · `/search` 的文本过滤形同虚设

**现象**：`GET /search?text=<任意串>` 恒返回该 tenant/viewer 作用域内的**全部**记忆，且分数为定值——不存在的串也照返。

**根因**：**参数名不一致**。处理器只读 `q`：

```go
// kernel/router.go:149-157
func (s *APIServer) handleSearch(w http.ResponseWriter, r *http.Request) {
    q := r.URL.Query()
    params := QueryParams{
        TenantID:    q.Get("tenant_id"),
        Viewer:      q.Get("viewer"),
        Text:        q.Get("q"),        // ← 只认 q
        ...
```

四处消费者的口径对照（R160 实测）：

| 消费者 | 实际使用 | 与处理器一致？ |
|---|---|---|
| `kernel/router.go:154`（处理器） | `q` | —（真源） |
| `sdk/python/lightmem_sdk.py` `search()` | `q` | ✅ |
| `sdk/js/lightmem-sdk.js:175` `search()` | `q` | ✅ |
| `README.md` 快速开始示例 | `text` | ❌ |
| `integrations/dsh-mcp-bridge/lightmem_mcp_bridge.py` | `text` | ❌（照抄 README 所致） |

**后果链**：用 `text=` → `QueryParams.Text` 为空 → 后端**跳过文本过滤**：
- `kernel/backend_sqlite.go:135-137`：空 needle → 每条 `score = 0.1`，返回全量；
- `kernel/backend_pg.go:237`：`if q.Text != ""` 为假 → 无 `LIKE` 条件，返回全量（按 confidence 排序）。

即：**空查询 = 列举作用域全部**。这不是后端 bug，而是参数没传对。

**连带**：R160 的 MCP 工具 `mcp__lightmem__lightmem_search` 因此只会「列举」，不能检索；DSH 侧必须改用 `lightmem_recall`。

### I-15 · Solo / SQLite 后端不持久化（严重）

**现象**：Solo 档写入成功，但**进程一重启，全部记忆丢失**；`data/` 目录始终为空，磁盘上不存在任何 `.sqlite` 文件。

**根因**：`kernel/backend_sqlite.go` 是**内存骨架**，其自身注释即自陈：

```go
// SQLite 存储后端（Solo 档，§5.4）
// 最小可运行骨架：内存表结构，仅用于跑通 Family 档装配链路。
// 生产实现应替换为 database/sql + sqlite-vec 扩展（§4.2 异步向量补全）。
type sqliteBackend struct {
    name string
    path string
    mu   sync.RWMutex
    data map[string]*Memory   // ← 全部在内存
}
```

`path` 只被赋值、**从不用于任何 I/O**；`/health` 如实暴露后端名为 `sqlite-skeleton/sqlite-vec`。R160 已用「写入→杀进程→重启→召回 0 命中」实测确认。

**影响面**：Solo 是「个人 / 开发测试」档，也是**零外部依赖**档（Family 起才需要 PG）。对外承诺「长期记忆」却无法跨重启存活，属功能级缺陷。R160 的持久化部署已绕开该档（改走 pgvector），但**缺陷本身仍在**。

## 三、泳道详述

### A 线 —— `/search` 文本过滤修复与口径统一

**目标**：让 `GET /search` 的文本过滤真正生效，且 README / 两个 SDK / MCP 桥四处口径一致。

**做法（默认按「兼容」落地，零破坏）**：
1. `kernel/router.go` 的 `handleSearch` 改为 **`q` 优先、`text` 兜底**：
   ```go
   text := q.Get("q")
   if text == "" {
       text = q.Get("text")   // 兼容 README/历史调用方
   }
   ```
2. **明确空查询语义**（二选一，需在此线内定稿并写进文档）：
   - 维持现状「空 = 列举作用域全部」，但必须在 README 写明；
   - 或空查询返回 `400 {"error":"q or text required"}`，避免误用成「全量导出」。
3. 统一消费者口径：`README.md` 的 `/search` 示例、`integrations/dsh-mcp-bridge/lightmem_mcp_bridge.py`
   的 `tool_search()` 改为发送 `q`（并保留 `text` 以兼容未来服务端）。
4. 新增 `kernel/router_search_test.go`：覆盖 `q` 命中 / `text` 命中 / 无匹配 / 空查询 / tenant 隔离。

**验收标准**：
- 以 `q=` 与 `text=` 传同一**不存在的**串，均返回**空集**（当前返回全量，即回归失败）；
- 以二者传同一**存在**的串，均返回该条；
- 空查询行为与文档一致；
- `grep -n 'text=' README.md` 与桥实现口径一致；
- 新增测试在 0.88 全 PASS。

---

### B 线 —— Solo / SQLite 后端持久化（**有决策门**）

**目标**：让 Solo 档的记忆能跨进程重启存活；若最终裁定不实现，则必须**如实降级标注**，不得保留「长期记忆」的误导性承诺。

**方案门**：

- **方案 a（真 SQLite，触红线⑦）**
  - `database/sql` + 驱动：`modernc.org/sqlite`（纯 Go、无 cgo）或 `github.com/mattn/go-sqlite3`（cgo，需 `libsqlite3`）。
  - 优点：真 SQL、可上 sqlite-vec、与 PG 档语义最接近。
  - 代价：**新增第三方依赖**，破 R17 以来「grpc/protobuf 是唯一例外」的纪律；纯 Go 驱动体积大，cgo 驱动给 0.88 的 jail 部署增加库依赖。
- **方案 b（stdlib-only 落盘，零依赖）**
  - 保留现有 `StorageBackend` 接口，把 `map` 换成「内存索引 + 追加日志（JSONL）+ 周期性原子快照（`os.Rename` 替换）」。
  - 优点：零新增依赖，保住 Solo「零外部依赖」定位；实现可控。
  - 代价：非 SQL，无 `sqlite-vec` 向量能力（现有 `VectorSearch` 本就返回「不支持」并由调度层降级，无回归）。
- **方案 c（明确降级，最低成本）**
  - 把 Solo 档如实定位为「内存档 / 演示档」：改 `profiles/lims-solo.profile.yaml` 注释、README 档位表、
    并让 `/health` 与 `kernel/backend_sqlite.go` 的 `Name()` 明确写「non-persistent」。
  - 优点：零风险、诚实。
  - 代价：Solo 档不再是可用的长期记忆（个人用户被迫上 PG）。

**交付物（按裁定结果）**：
- `kernel/backend_sqlite.go`（方案 a/b 为实现；方案 c 为命名与注释如实化）
- `kernel/backend_sqlite_persist_test.go`（**方案 a/b 必交**）：覆盖「写入 → 关闭后端 → 重开后仍在」、
  跨实例可见性隔离、幂等键、并发写入、以及 17 个接口方法的持久化行为
- `kernel/go.mod` / `go.sum`（**仅方案 a**）
- `profiles/lims-solo.profile.yaml` + `README.md`（档位语义如实化）
- `lightmem.md` 缺陷账新增条目（L-2xx）与关闭记录

**验收标准**：
- 方案 a/b：`go test -count=1 -run 'Persist' ./kernel/` 全 PASS，且测试**真实证明**「重建后端实例后数据仍在」
  （禁止只测内存路径）；
- 方案 a/b：`/health` 的后端名不再含 `skeleton`；
- 方案 c：文档/注释/`Name()` 三处一致标注非持久化，且 README 不再宣称 Solo 可长期保存；
- 任一方案：`go vet ./kernel/` rc=0；`go test -count=1 ./kernel/` 全 PASS（既有用例零回归）。
