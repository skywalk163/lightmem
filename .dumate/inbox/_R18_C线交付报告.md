## 三、qdrant 档复跑（交付物 1）

**档位 profile**：`/tmp/r18/profiles/lims-smb-qdrant-r18c.profile.yaml`——`profiles/lims-smb.profile.yaml` 的临时副本，仅 `storage_backend: pgvector → qdrant` 一处改动（`qdrant.enabled=true`、`host=10.0.10.60`、`port=6333` 保持 R17 S2 对齐实机值，既有 profile 语义未改）。`kernel.LoadProfile` 自检输出：`tier=smb backend=qdrant qdrant={Host:10.0.10.60 Port:6333}`。

**运行命令**（0.88，仓库根）：

```sh
cd /tmp/r18/lightmem
go run ./r18c_harness/ \
  -profile /tmp/r18/profiles/lims-smb-qdrant-r18c.profile.yaml \
  -holdout eval/holdout/holdout_v2.jsonl \
  -weights eval/weights/rank_weights_en_r5.json \
  -embedder vector -topk 5 -now-fixed 2026-10-14 \
  -report polaris_r18_qdrant -reports-dir eval/reports
```

**实测（报告 `config` 自证）**：`backend=qdrant`、`backend_source=smb/qdrant`、`profile_tier=smb`、`embedder=vector:BAAI/bge-m3`、`holdout=eval/holdout/holdout_v2.jsonl`、`now_fixed=2026-10-14`。用例耗时 **190.40s real**（含 800 条记忆逐条写入真机 Qdrant + 逐条 4 层 scan 召回）。

**真机读写证据**：

- 集合 `lightmem_memories`（dim=1024 / Cosine）在 0.88 实测 `points_count`：运行前 **0**（预清后）→ 运行中随逐条写入增至数百（断点观测 351 / 561；800 条 holdout 各 1 条 memory，终态 800）→ 收尾清理后 **0**（无残留）。
- 前置/收尾各按 tenant 过滤器删除 `t-beam`（600 条）/`t-lc-v2`（200 条）——这是 holdout_v2 的两个 tenant（800 条全为 L1 层），保证幂等与数据卫生。
- 该档召回路径为 `ScanLayer`（真机 scroll）+ 文本/实体/语义信号在 Fact 文本上**即时** embed（`semanticPathVector`），不依赖后端存量向量，故与 SQLite 骨架口径同源可比。
