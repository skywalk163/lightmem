## 三、泳道详述

### A 线 —— PG e2e 缺陷账清零（confidence 精度 + 夹具隔离）

**目标**：清零 R17 §5 登记的两个 pg e2e 预存缺陷，使 `eval/e2e/pg` 在 fresh 库上 0 红。

**A1 · pg e2e 夹具隔离（安全，无 Schema 变更）**
- 现象：`TestPgUpsertGetRoundtrip` / `TestPgIdempotencyKey` 的 Version 断言 `got 4/8, want 1/2`，根因 `lightmem_test` 库历史残留。
- 修复（二选一或二者兼施，均不碰 SQL）：
  1. 用例前置 `TRUNCATE` 相关表（推荐，彻底隔离）；
  2. 改用**唯一 tenant 前缀**（R10-B 建议项，一直未实施）——每次测试用 `tenant = fmt.Sprintf("test_%d_%d", os.Getpid(), time.Now().UnixNano())` 隔离。
- 验收：`cd kernel && go test -count=1 ./eval/e2e/pg/...` 在 fresh 库全 PASS；重复跑无 Version 残留干扰。

**A2 · confidence 精度修复（⚠️ 触及红线①③，需业主裁定）**

> **双方案门（Agent 在业主裁定前只执行 A2-b，不碰迁移 SQL）**：

- **方案 a（Schema 对齐，推荐但触红线）**：`kernel/migrations/001_pgvector.up.sql` 中 `confidence real` → `double precision`，与 `Memory.Confidence` float64 一致。
  - fresh 库（按当前迁移新建）立即生效；
  - **既有库**（若已按 `real` 创建 float4 列）需 `ALTER TABLE ... ALTER COLUMN confidence TYPE double precision`，因触及**红线③「既有 SQL 不动」**，**必须业主裁定**后才可执行；R10 期 float8 库本身无需 ALTER。
- **方案 b（安全兜底，零 Schema 变更）**：e2e 断言改容差——比对 `Memory.Confidence`(float64) 与回读 float4 的误差带（如 `assert.InDelta(want, got, 1e-6)`），不动任何 SQL。

**交付物**：
- `eval/e2e/pg/*_test.go`（修改：TRUNCATE / 唯一 tenant 前缀 + 容差断言）
- `kernel/migrations/001_pgvector.up.sql`（**仅方案 a 且业主裁定后**改 `double precision`）
- 缺陷账更新：L-216 关闭记录写入 `lightmem.md` D 段（含实际处置：方案 a/b + 既有库 ALTER 裁定结论）

**验收标准**：
- `go test -count=1 ./eval/e2e/pg/...` 全 PASS（fresh 库，0.88 实测）
- 红线 diff：方案 a 时 `git diff` 仅含 `001_pgvector.up.sql` 的 `real`→`double precision` 单行 + e2e 测试；方案 b 时零 SQL 改动
- 既有北极星 `eval/reports/polaris_*` 零改动（红线②）

### B 线 —— T2 多 jail gRPC 真机联调

**目标**：把 R17 S3 的本地回环 gRPC 推到真机多 jail：coordinator 落 `lims-router:9443`，多 jail worker 走 gRPC `Query`（跨节点召回）+ `Revoke`（撤销广播）真机跑通。

**前置条件**（R17 已满足）：
- jail 网络就绪：lims-pg(10.0.10.10) / lims-qdrant(10.0.10.60) / lims-router / lims-minio 同 `10.0.10.0/24`，pf 内网全放行（R17 S1 完成）
- gRPC 代码已交付（`kernel/node_rpc*.go` + `kernel/proto/`），默认关守护 `TestNodeRPCWiringDefaultOff` 在

**执行步骤**：

```sh
# 1) pf 放行 9443（内部网，参考手册 §11A.7.3）
#    manuals/pf.rules 的 <lims_jails> 表已含各 jail IP；
#    确认内部网 pass 规则覆盖 9443，或显式：
#      pass in on $int_if proto tcp from <lims_jails> to <lims_jails> port 9443 keep state

# 2) coordinator 起在 lims-router:9443
#    profile.features.cross_node_rank_merge = true
#    lims-router jail 内启动 lightmem-k，监听 :9443（GRPCNodeRegistry Server）

# 3) ≥2 个 worker jail（如 lims-pg / lims-qdrant）注册到 coordinator
#    走 gRPC Heartbeat / Register；验证 List/PurgeStale

# 4) 真机跨节点 Query + Revoke 联调
#    - Query：coordinator 向 worker 发 gRPC Query，回收候选并本地 rank merge
#    - Revoke：coordinator 广播 Revoke，worker 执行撤销并回包

# 5) 新增 env-gated 真机联调测试 kernel/node_rpc_e2e_jail_test.go
#    LIGHTMEM_GRPC_E2E=1 时跑多 jail 联调；未配置显式 SKIP（与 R15/17 门禁同口径）
```

**关键**：本机（Windows）只出命令/脚本；实机在 0.88 由用户或 workbuddy 执行。默认关守护不变（红线④）；新增测试 env-gated，不配置则 SKIP 不假 PASS。
