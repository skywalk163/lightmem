## 1. A 路 — 真实向量 embedder 接入 + reference_frame 权重重校准

### A.0 范围与红线澄清

- **允许**：新增 `kernel/embedder_vector.go` 实现 `kernel.Embedder` 接口（R4-D 已预留）；引入确定性向量模型（BGE / text-embedding-3 等，须固定 seed、不调 LLM 做排序）；重跑 `eval/tune_rank_weights_v2.go` 把 reference_frame 纳入可变量。
- **禁止**：用 LLM 做检索排序或事实判断；改动 `Memory`/`RouterContext` Schema。
- **前置**：`kernel/embedder.go`（R4-D）已定义 `Embedder` 接口：`Embed(text string) ([]float32, error)` + `Dim() int` + `Name() string`；`kernel/embedder_tfidf.go` 的 `CharNgramEmbedder` 已实现该接口。

### A.1 背景（根因，R4-B §3.4 + R4-A §5）

**R4-B §3.4**：reference_frame 信号本身有 **100% 区分度**，但 R3-A 权重搜索阶段没有变化样本可供校准，坐标下降把权重落到 0.0。rf=4.0 对照时 ref 桶 top-1 从 0% 升到 46.7%。**结论：信号有效但权重被关闭。**

**R4-A §5**：公开基准 9 条 multi-hop top-1 失败中 5 条被 L1/L2 修复，剩余 **4 条全部是 LoCoMo 对话样本**——答案是跨轮推断，目标 turn 与 query 之间不存在字面前缀关系，且 2 条连召回都没进 top-5。**这类需要真实语义向量（BGE 等）或 LLM 语义匹配**，R4-D `Embedder` 接口已预留。

**R4-B §4.3**：char n-gram embedder 对合成集拖累 −1.5pp（fact / top-1），词表由公开集+合成集联合构建，对合成集短模板查询引入偏差。

### A.2 目标

1. **真实向量 embedder 接入**：实现 `kernel/embedder_vector.go`，支持 BGE 等本地可运行的向量模型（`onnxruntime` / `llama.cpp` / 静态向量文件），通过 `Embedder` 接口接入，`run_kpi.go` 新增 `-embedder vector|tfidf|none` 切换。
2. **reference_frame 权重重校准**：基于 `eval/dataset/reference_frame.jsonl`（60 条）+ 公开基准 + 合成集，重跑坐标下降，把 `reference_frame` 纳入可变量。
3. **LoCoMo 4 条修复**：向量匹配后重新评测，确认至少 2 条被修复。
4. **公开基准 MRR 不回归**：≥ 0.9845；其余桶不回归。
5. **L3 上下文增强重新评估**：接向量模型后重跑 depth=2，若 open-domain/temporal 不回归则启用。

### A.3 交付

1. **`kernel/embedder_vector.go`（新增）**：
   - 实现 `kernel.Embedder` 接口；加载本地向量模型（onnxruntime / llama.cpp / 静态 `.npy`+`.json` 词向量）。
   - **确定性**：embedding 结果固定（seed=42，模型加载路径固定），`Name()` 返回 `"vector:<model>"`。
   - **降级**：模型文件缺失时报错并提示回退 `-embedder tfidf`。
   - **不调 LLM**：只做向量化嵌入，不做排序/事实判断。
2. **`kernel/embedder.go`（修改）**：`RankFusion.SetEmbedder` 保持向后兼容（接受 `func(string) ([]float32, error)` 与 `Embedder` 接口两种）；新增 `SetEmbedderVector` 或 `NewVectorEmbedder` 工厂函数。
3. **`kernel/rank_fusion.go`（修改）**：`signalReferenceFrame` 打分保持 R3-A 修复后语义（空帧 0.5 中性）；仅调整调用路径以支持向量信号参与 RRF 融合（semantic 从 `RecallScore` 切换到向量余弦相似度）。
4. **`eval/tune_rank_weights_v2.go`（修改）**：坐标下降可变量从 4 个（semantic/keyword/entity/feedback）扩展到 **8 个**（含 reference_frame / value / freshness / source_trust），初始值取 R4 联合权重。
5. **`eval/run_kpi.go`（修改）**：新增 `-embedder <tfidf|vector|none>` flag；参考 R4-B 的 `RefFrameSignal` 指标输出；重校准后 reference_frame 权重生效时复检 ref 桶 top-1 传导率。
6. **报告**：`eval/reports/vector_embedder_and_reframe_<ts>.md`：
   - 向量 embedder 设计、模型来源、维度、加载方式
   - reference_frame 权重重校准结果（纳入可变量前后对比，基于 60 条评测集）
   - LoCoMo 4 条逐条分析（向量匹配是否修复）
   - 公开/合成 MRR 不回归对照
   - L3 上下文增强重评估（depth=1 vs depth=2）

## 2. B 路 — 合成集 multi-hop 样本重构 + temporal 标记样本补齐 + fact 边界归一化

### B.0 范围与红线澄清

- **允许**：修改合成集样本生成逻辑（`eval/eval_generate.go`），把 multi-hop `ExpectedMemoryID` 从双元素重构为单元素（最终答案）；新增 temporal 标记样本生成器 `eval/generate_temporal.go`；在 `eval/run_kpi.go` 新增 fact 边界归一化补判。
- **禁止**：改动 kernel Schema；用 LLM 生成样本。
- **前置**：合成集样本由 `eval/eval_generate.go` 生成，multi-hop 链条 `hop-1 → hop-2`；R4-D 报告已确认主 MRR 0.500 是结构性惩罚（样本 `ExpectedMemoryID` 双元素、检索器正确召回 hop-2 却按 rank=2 计）。

### B.1 背景（根因，R4-D §1 + R4-C §9）

**R4-D §1**：合成集 150 条 multi-hop 全部主 MRR=0.500，因为样本 `ExpectedMemoryID = []string{memID1, memID2}` 把**跳板 hop-1 放在优先级更高的 [0] 位**，而检索器正确召回的是最终答案 hop-2（`Expected[1]`，RR=0.5）。**不是检索器错误，是样本评分口径的结构性惩罚。**

**R4-C §9.2**：公开基准存在 beam fp，v4 已剔除 93 条模板 expected，但 C 独立口径下 fact 假阳性仍 5 条（0.77%）。

**R4 收口 §5**：时序桶准确率 0.0%（公开基准无 temporal 标记样本）；多信号融合准确率 0.0%（multi-hop 桶待人工复核）。

### B.2 目标

1. **合成集 multi-hop 样本重构**：`ExpectedMemoryID` 改为单元素（hop-2 最终答案），消除 0.500 结构性惩罚。
2. **temporal 标记样本补齐**：新增 ≥ 50 条带 `is_temporal=true` 的公开/合成样本，覆盖多时间点查询（as_of / 窗口 / 因果），验证 temporal 桶准确率。
3. **fact 边界归一化**：对短 expected 做确定性边界归一化（数值/日期/单位/大小写），把 C 独立口径假阳性从 5 条降到 ≤ 3 条。
4. **公开/合成 MRR 不回归**：分别 ≥ 0.9845 / ≥ 0.8585。

### B.3 交付

1. **`eval/eval_generate.go`（修改）**：
   - multi-hop 样本 `ExpectedMemoryID` 从双元素改为**单元素**（hop-2 最终答案 ID）。
   - 保留原双元素样本到 `dataset/all_multihop_dual.jsonl`（历史可比性，不覆盖 `all.jsonl` 的历史口径——**或**在 `all.jsonl` 中新增字段 `expected_dual` 同时保留两种判定）。
   - **只增不改**：不删原字段，新增 `ExpectedMemoryIDPrimary`（最终答案）与 `ExpectedMemoryIDHop`（跳板）。
2. **`eval/generate_temporal.go`（新增，`//go:build ignore`）**：

   - seed=42 固定采样；不调 LLM；模板替换。
   - 输出 `eval/dataset/temporal.jsonl`（合并到 `all.jsonl` 的 `temporal` 桶）。
3. **`eval/run_kpi.go`（修改）**：
   - 新增 `-temporal-samples <path>` flag：加载 temporal 样本合并评测。
   - 新增 `-fact-normalize` flag（默认 true）：fact 匹配前做确定性边界归一化（数值 `$3,750` → `3750`、日期 `2023-04-01` → `20230401`、单位大小写统一）。
   - multi-hop 主 MRR 判定改用 `ExpectedMemoryIDPrimary`（单元素）；同时输出 `ExpectedMemoryIDHop` 作为 hop 口径对照。
4. **`eval/run_kpi_fact_test.go`（修改）**：新增 fact 边界归一化单测（数值/日期/单位/大小写/混合样本）。
5. **报告**：`eval/reports/synth_multihop_rebuild_and_temporal_<ts>.md`：
