## 三、根因与修复

### 3.1 I-12 根因（复述实测证据）

处理器只读 `q`（`kernel/router.go:154` 旧代码 `Text: q.Get("q")`），而 README 示例用 `text=`；
`text=` 调用 → `QueryParams.Text` 为空 → 后端**跳过文本过滤**：
`backend_sqlite.go` 空 needle 每条 `score = 0.1 + confidence*0.2`（本例 0.88）→ 返回作用域全量；
`backend_pg.go` 的 `if q.Text != ""` 为假 → 无 `LIKE` 条件。

### 3.2 修复（`kernel/router.go`，仅 `handleSearch`）

```go
tenant := q.Get("tenant_id")            // 缺 → 400 tenant_id required
text := strings.TrimSpace(q.Get("q"))   // q 优先
if text == "" {
    text = strings.TrimSpace(q.Get("text"))  // text 兜底
}
if text == "" {                          // 空查询 → 400，不再等于「列举全部」
    writeJSON(w, http.StatusBadRequest, map[string]string{"error": "q or text required"})
    return
}
...
if res == nil {                          // 后端无命中是 nil slice → 编码成 null
    res = []QueryResult{}                // 统一为 []
}
```

**为什么空查询选 400 而不是「维持列举」**：

1. `docs/api.md` 的状态码表**本来就承诺**「400 缺少 `tenant_id` 或 `q`」，代码一直没实现——本线是把文档承诺补齐，而不是新造行为；
2. 「空查询 = 列举作用域全部」是 R160 I-12 被误读成「过滤失效」的直接诱因，也是**误用成全量导出**的入口；真要导出已有 `POST /api/v1/gdpr/export`；
3. 仓库内**全部消费者**（两个 SDK、MCP 桥、`eval/e2e` 助手、`eval/scripts/r11c_family_start.sh`）都传非空文本 + `tenant_id`，实测零破坏。

**附带的两处小修**（同属「口径一致」，不涉后端）：

- 查询串**两端空白裁剪**：`text = "  ERP  "` 旧行为在 PG 上 `%  erp  %` 永远匹配不上，现可命中；
- 无命中统一返回 `[]`：旧行为返回 `null`，客户端需额外判空（MCP 桥注释里就记着这个坑）。
