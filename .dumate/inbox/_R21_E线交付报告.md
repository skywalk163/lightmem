## 4. ⚠️ 新发现 G8 —— PG 后端 private 记忆越权泄露（**P0 安全缺陷**）

### 4.1 现象（隔离租户 `r21leak` 复现，无歧义）

| viewer | `/search?q=zzq&tenant_id=r21leak` 返回 | 判定 |
|---|---|---|
| **不传 viewer** | `['leak-priv', 'leak-tenant']` | ❌ **private 被泄露** |
| `viewer=owner-b`（异用户） | `['leak-priv', 'leak-tenant']` | ❌ **private 被泄露** |
| `viewer=owner-a`（本人） | `['leak-priv', 'leak-tenant']` | ✅ 正确 |

`leak-priv` 的 `visibility=private`、`user_id=owner-a`；**任何同租户 viewer（含不传 viewer）都能搜到它**。

### 4.2 根因：PG 的 SQL 谓词与规范 `canView` 语义分叉

**规范语义**（`kernel/backend_sqlite.go:512` `canView`，SQLite 与 Qdrant 均遵守）：

```go
case VisPrivate:    return viewer != "" && m.UserID == viewer      // 仅 owner
case VisSharedUser: return viewer != "" && (m.UserID == viewer || readers 含 viewer)
case VisTenant:     return tenant != "" && m.TenantID == tenant
case VisCrossTenant:return tenant != "" && shared_with_tenants 含 tenant
```

**PG 实际 SQL**（`kernel/backend_pg.go:232`）：

```sql
(visibility = $1                                    -- $1 = q.Viewer ← 把“viewer”当成了 visibility 枚举值
 OR (visibility = 'shared_user' AND permission->'readers' ? $2)
 OR tenant_id = $3                                  -- ← 'private' 落进这个分支，同租户全可见
 OR $3 = ANY(shared_with_tenants))
```

两个独立缺陷：

1. **`visibility = $1` 语义错位**：`$1` 传的是 `q.Viewer`（用户名），而 `visibility` 是枚举（`private`/`tenant`/…）。二者永不相等 → **该分支恒为假**，等于没做 owner 校验。
2. **`tenant_id = $3` 无差别放行**：任何 `tenant_id` 匹配的行都被放行，**包括 `visibility='private'` 的行** → private 对同租户所有人可见。

> `VectorSearch` 同样写法（`backend_pg.go:315`），**同一根因，需一并修**。

### 4.3 为何此前未暴露

- **SQLite / Qdrant 后端正确**（走 `canView`），只有 **PG 分叉**。
- 但 0.88 生产档正是 **family + pgvector**（`lims-family.profile.yaml:15`）→ **生产环境受此影响**。
- `router_search_test.go` 的 `TestSearchViewerPrivateIsolation`（第 235 行）**跑在 SQLite 后端上**，因此该单测**永远测不到 PG 的这条分叉** → 绿灯是假象。
- 影响面：`/search`、`/search/vector`、以及任何经 `backend.Query` 的路径（含 MCP `lightmem_search`）。

### 4.4 危害

| 维度 | 影响 |
|---|---|
| 安全 | **`private` 承诺被打破** —— 违反 `lightmem.md` §3.2「`visibility` 为硬过滤（安全边界），禁止降级为后置过滤」 |
| 合规 | §7.1 可见性规则失效，可能构成越权读取 |
| 共享大脑 | 多 Agent 共享场景下，A Agent 的私有记忆对全租户可见 → **不可接受** |

### 4.5 处置建议（已写入任务书 B 线）

**只修 PG 的谓词，不改 Schema、不改 SQL 迁移、不动其他后端** —— 把 PG 的可见性谓词与 `canView` 语义**对齐**：

```sql
-- 建议形态（与 canView 逐条对应；用 pre-filter，红线允许）
(
  (visibility = 'private'     AND user_id = $viewer AND $viewer <> '')
  OR (visibility = 'shared_user' AND (user_id = $viewer OR permission->'readers' ? $viewer))
  OR (visibility = 'tenant'      AND tenant_id = $tenant)
  OR (visibility = 'cross_tenant' AND $tenant = ANY(shared_with_tenants))
)
```

**必配真机测试**：新增 **PG 专用**（env-gated，`LIMS_TEST_PG_*`）的可见性测试——**必须覆盖「不传 viewer」与「异用户 viewer」两条越权路径**，并在 0.88 上真跑（`eval/e2e/pg/` 已有 PG 真机基础设施可复用）。**不允许只靠 SQLite 单测**（这正是本次漏网的直接原因）。
