### 2.2 脚本设计（纯 POSIX sh + zfs/ssh，无第三方依赖）

- **子命令**：`snapshot` / `prune` / `send` / `all` / `list` / `rollback`
- **选项**：`-p POOL/DS`（源根，默认 tank/lims）、`-r`（递归）、`-t hourly|daily|weekly`、`-k N`（保留数，默认 48/7/4）、`-d DEST`（`host:pool/ds` 远程 ssh 或 `pool/ds` 本地第二池）、`-s DS@SNAP`（回滚目标）、`-n`（dry-run）
- **退出码**：0 成功 / 1 运行期失败 / 2 参数错误 / 3 环境缺失（无 zfs）
- **设计要点**：
  1. **只增不改**：`prune` 只删本脚本命名规范内快照（`@<TYPE>-*`），人工/第三方快照不碰；`rollback` 为显式人工动作，不进入 `all` 自动链路；
  2. **幂等**：同时间戳快照已存在则 `SKIP`；
  3. **增量发送**：源与目标存在共同快照时用 `zfs send -i <common>`，否则退回全量；目标已最新则 `SKIP`；
  4. **确定性命名**：`<ds>@<TYPE>-<YYYYMMDDHHMMSS>`，可 grep/排序；
  5. **递归映射**：`-r` 时按数据集层级一一映射到目标池；
  6. 远程 ssh 已加 `-o BatchMode=yes -o ConnectTimeout=10`，避免无 TTY 卡死。

### 2.3 手册章节（§10）

覆盖：ZFS 快照策略与保留窗口、`zfs_backup.sh` 各子命令用法与示例、`/etc/crontab` 定时（hourly/daily/weekly 三档）、`zfs send` 异地/本地容灾链路、`rollback` 恢复演练步骤、故障排查要点。并在手册 §5.6 映射表补 `| 第 10 节 快照容灾实操（R16-S7） | §5.6「快照与容灾」 |`。

### 门禁根因修复（golden 测试 CRLF）

**现象**：首跑门禁时 `kernel` 的 `TestPrometheusTextGolden` 与 `TestPrometheusTextGolden_Empty` FAIL（golden 输出不匹配），单独 `-run` 与全量均复现。

**根因**：`kernel/testdata/*.golden` 在 0.88 上为 **CRLF**（`server_metrics.golden` 45 行、`server_metrics_empty.golden` 38 行），而 Go 侧 `PrometheusText()` 输出 LF。仓库 `.gitattributes` 有 `* text=auto` 与多条 `eol=lf` 规则（`*.go/*.sh/*.json/…`），**但缺 `.golden` 规则**；本机（Windows，`core.autocrlf=true`）打包/导出时未覆盖该后缀，导致 golden 被转成 CRLF。属**传输工件，非代码缺陷**；仓库内 blob 本身为 LF。

**修复（中心点一次修）**：

```diff
 # .gitattributes
 *.yml   text eol=lf
+*.txt    text eol=lf
+*.golden text eol=lf
```

修复后 `git check-attr` 确认 `*.golden → eol: lf`；同步将 0.88 工作树内两 golden 归一为 LF，**门禁转绿（PASS 12/FAIL 0）**。
