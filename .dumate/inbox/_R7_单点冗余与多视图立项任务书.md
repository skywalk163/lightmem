## 1. A 路 — semantic 单点冗余加固（Q1）

### A.1 背景（根因，来自 R6-D §2）

R6-D 消融：关闭 semantic 后 M1 从 0.9525 降到 0.7458（−20.68pp，保留率 0.725），其余 7 路关闭后降幅 ≤5pp。**semantic 承担了大部分「语义消歧 + 跨槽值匹配」工作**，但当前它是**单一实现**——`semanticScore()` 内部只有一条通路（单向量 + 单相似度度量）。

千脑答案：冗余=多实现并存的优雅降级。语义理解不应依赖单条通路，应有多条**互补的**语义路径同时工作。

### A.2 范围与红线澄清

- **允许**：
  - 在 kernel 内为 semantic 信号**新增**互补实现（如：现有向量相似度之外的第二/第三路径——例如 slot-value 结构匹配、字段级对齐、或基于已存在索引的确定性匹配），只增不改。
  - semantic 融合从「单值加权」升级为「多路径语义解释投票」，复用 R6-A 的 `ConsensusVoter`。
  - 新增 `eval/polaris/polaris_semantic_redundancy.go` 评测：逐路径消融、多路径冗余度度量、消融后整体 M1 不降。
- **禁止**：改 `Memory`/`RouterContext`/`RecalledCandidate` 既有字段语义；引入 LLM/BGE-M3 等新模型（超红线范围）；改动现有 `semanticScore()` 既有行为（可新增旁路，不修改原路径）。
- **前置**：R6-A 的 `ConsensusVoter`（`kernel/voting.go`）已就绪，可直接复用做多路径语义投票。

### A.3 交付

1. **kernel 语义多路径（新增，只增不改）**：
   - 为 semantic 信号新增至少 2 条**互补**路径（现有向量相似度为路径 0 保留不动）：
     - 路径 1：**slot-value 结构匹配**（候选的字段与查询字段按名对齐，值重叠度加权，确定性、零向量依赖）；
     - 路径 2：**跨字段互信息匹配** 或 **查询-候选 token 共现加权的确定性相似度**（实现者选定，需在报告中说明选型理由）。
   - 多路径解释输出 top-K 后，接入 R6-A 的 `ConsensusVoter` 产出语义共识序 + 语义分歧度。
   - **默认关闭**（flag 门控，如 `-semantic-redundant`），保证不回归；开启后语义融合用多路径投票替代单值加权。
2. **`eval/polaris/polaris_semantic_redundancy.go`（新增）**：
   - 逐路径消融（关一路看整体 M1 降幅）；
   - 冗余度度量：**任一路关闭降幅 ≤5pp** 达标（对齐 R6-D 消融口径）；
   - 与 R6-D 单路径消融对照（同口径、同 seed、同语料）。
3. **报告**：`eval/reports/semantic_redundancy_<ts>.md`——多路径设计、逐路径消融表、与 R6-D 单路径对照、北极星整体 M1 不回归证明。

## 2. B 路 — 确定性多视图模板升级（Q2）

### B.1 背景（根因，来自 R6-D §3）

R6-D 多视图：4 个**回退模板**（原 query + "？" / "请查询" + 原 query / 原 query + "，帮我查一下"）投票集成 M1=0.8339，**低于**基线 view_0 的 0.9525（−11.86pp）。

根因：三个回退视图只是**加了语气助词/引导词**，并没有提供**新的语义视角**——它们本质是原 query 的**噪声副本**，与 view_0 高度相关且命中概率更低。投票把它们拉进 top-K，反而稀释了 view_0 的正确排序。

千脑答案：多视图探测应提供**语义等价但结构不同的视图**——如同一个问题从多个角度问（一物多帧），视图之间应**低相关、高互补**，集成才有增益。

### B.2 范围与红线澄清

- **允许**：
  - 新增**确定性**视图生成器：基于结构化字段（tenant/entity/scene/task/时间戳/槽值）的**重排组合**，而非加语气词。例如：
    - view：把 query 中**关键槽值对**（`entity=客户A, value=X`）重排成「X 的归属主体是客户A」；
    - view：把 query 转成**多帧探测**（用 entity 帧 / scene 帧 / task 帧分别构造子 query）；
    - view：槽值**字段级**倒置（值→键）或**枚举候选**视图（把候选 top-K 作为查询回读）。
  - 复用 R6-A 的 `ConsensusVoter` 做视图级投票，并计算**视图间分歧度**。
  - 新增 `eval/polaris/polaris_multiview_v2.go` 评测：新旧模板对照、视图间相关性/互补性度量、集成 M1 vs 单视图基线。
- **禁止**：LLM 改写 query；改动现有 R6-D 的 `generateMultiviews` 行为（可新增 v2 生成器，不修改原实现）；引入外部模型。
- **前置**：R6-A 的 `ConsensusVoter` 就绪；R6-D 的 `generateMultiviews`/`stripAnchor` 已实现，可直接复用其接口。

### B.3 交付

1. **`kernel/` 或 `eval/polaris/` 新增确定性视图生成器（只增不改）**：
   - 设计 **≥3 个结构等价但视角不同**的视图（实现者选定，报告中说明选型理由与互斥性）：
     - **v1：槽值倒装**——query 的 `entity / value` 对重排为 `value 属于 entity` 形式；
     - **v2：多帧子查询**——从 query 抽 entity 帧 / scene 帧 / task 帧分别生成子 query；
     - **v3：候选回读**——把 baseline 检索 top-K 候选作为**回读 query**（千脑「思考=在参考系中运动」的具体化：在候选的知识组织里运动）。
   - 视图间**低相关**设计（报告中量化：视图间命中重叠率 ≤ 某个阈值，实现者定但需给出度量值）。
2. **视图级投票集成**：多视图各自产出 top-K 后，用 R6-A 的 `ConsensusVoter` 集成；分歧度 side-channel 输出。
3. **`eval/polaris/polaris_multiview_v2.go`（新增）**：
   - 新旧模板对照：v1/v2/v3 与 R6-D 回退模板的 M1 对比；
   - 视图间互补性度量（重叠率 / 互补增益）；
   - 集成 M1 vs 单视图基线（**目标：≥ 单视图，即 ≥0.9525**）。
4. **报告**：`eval/reports/multiview_v2_<ts>.md`——模板设计、视图间互补性、新旧对照、集成 M1 判定。
