## 三、接口冻结（T0 必读，**三条泳道据此并行，不得各自发明**）

> 这是本轮**唯一**的跨线耦合点。冻结后 A/B/C 三线文件域严格不相交。

### 3.1 身份 API（B 线提供，A/C 线消费）

```go
// kernel/auth.go（B 线新增）
package kernel

// Identity 由 token 解析出的可信身份；服务端唯一真源。
type Identity struct {
    AgentID  string // 必填：哪个 Agent 在操作
    UserID   string // 必填：以哪个用户身份（决定 private 可见性）
    TenantID string // 必填：租户边界
}

// IdentityFromContext 从请求 context 取身份；未认证返回 ok=false。
func IdentityFromContext(ctx context.Context) (Identity, bool)

// AuthMiddleware 解析 token 并注入 Identity。
//   - 未配置 LIMS_AGENT_TOKENS 时：**透传**（向后兼容，红线④），并打一行 warn 日志；
//   - 已配置时：缺/错 token → 401 {"error":"unauthorized"}。
func AuthMiddleware(next http.Handler) http.Handler

// RequireIdentity 强制要求已认证身份（LIMS_REQUIRE_AUTH=1 时由 E 线挂载）。
func RequireIdentity(next http.Handler) http.Handler
```

**Token 配置格式（stdlib JSON，放 profile 或环境变量 `LIMS_AGENT_TOKENS`）**：

```json
{
  "t-dsh-8f3a…":   {"agent_id":"deepseek-harness","user_id":"dsh-agent","tenant_id":"dshteam"},
  "t-trae-…":      {"agent_id":"trae","user_id":"skywalk","tenant_id":"dshteam"},
  "t-workbuddy-…": {"agent_id":"workbuddy","user_id":"skywalk","tenant_id":"dshteam"},
  "t-raccoon-…":   {"agent_id":"raccoon","user_id":"skywalk","tenant_id":"dshteam"},
  "t-codearts-…":  {"agent_id":"codearts","user_id":"skywalk","tenant_id":"dshteam"},
  "t-opencode-…":  {"agent_id":"opencode","user_id":"skywalk","tenant_id":"dshteam"}
}
```

> **身份传递约定**：HTTP 请求头 `Authorization: Bearer <token>`（各家 MCP 客户端均支持 `headers`）。
> **写方身份强制**：`handleToolSave`/`update`/`feedback`/`forget` 的 actor **一律取 `IdentityFromContext`**；身份存在时**忽略 body 里的 `user_id`/`tenant_id`**（防冒充），身份不存在（未开启鉴权）时才回退 body 并记审计。
> **private 可见性特例**：`visibility=private` 的 owner 必须是 token 的 `user_id`，否则 403（防止把私有记忆写到别人名下）。

**目标**：让 lightmem **原生说 MCP**，一个 HTTP 端点服务所有支持 HTTP 的 Agent，同一二进制 `stdio` 模式服务只能吃 stdio 的 Agent。**彻底去掉 Python 桥这一跳。**

**做法**：

1. 新增 `kernel/mcp.go`：MCP 协议核心（`package kernel`，复用 `*APIServer`）。
   - 方法实现：`initialize`（**回显客户端请求的 protocolVersion**）、`notifications/initialized`、`tools/list`、`tools/call`、`ping`。
   - `server/discover`：可返回 `-32601`（DSH 会正常回退 legacy）；**若能低成本实现现代 era 则更好**，但**不得**因此阻塞交付。
   - 错误码遵循 JSON-RPC：`-32700` parse / `-32601` method not found / `-32602` invalid params；工具业务错误用 `isError: true` 的 tool result（**不要**用协议层错误）。
   - 工具清单 = §3.2 冻结表；每个工具 `inputSchema` **必须**照抄桥现口径（`lightmem_mcp_bridge.py:350-486`），并**补齐 `goal_detail` 与 `visibility`**（解 G3）。
2. 新增 `kernel/mcp_transport.go`：两种传输。
   - **stdio**：逐行读 stdin（**必须 `bufio.Scanner` 设大 buffer**，UTF-8 原样，不得做任何 GBK 转换——Go 默认 UTF-8，天然规避 R160 I-10）。
   - **streamable-http**：`POST /mcp`，请求 `Accept: application/json, text/event-stream`；响应按需 JSON 或 SSE（`text/event-stream`）；实现 `Mcp-Session-Id` 头（`initialize` 生成、后续请求携带）；支持 `GET /mcp`（SSE 流）与 `DELETE /mcp`（会话终止）为佳，至少保证 `POST` 完整可用。
3. 新增 `kernel/cmd/lightmem-mcp/main.go`：独立二进制，两个子命令/flag：
   - `-transport http -listen :18444`（**独立端口，不抢业务 18443**，`:18444` 专供 MCP-over-HTTP）
   - `-transport stdio`（供 CodeArts/Cline 直连，**无需 Python**）
   - 复用 `kernel.LoadProfile` + 同一后端；**必须**挂 B 线的 `AuthMiddleware`。
4. 新增 `kernel/mcp_test.go`（≥12 个 `Test` 函数）：`initialize` 版本回显、`tools/list` 数量与 schema 完整性、`tools/call` 成功/未知工具/缺参、JSON-RPC 错误码、**中文 UTF-8 往返**、stdio 多行 framing、HTTP 会话头、**`goal_detail` 透传不再 422**。

**验收标准**：
- DSH 以 `transport: streamable-http` + `url: http://192.168.0.88:18444/mcp` 接入，**7+6 个工具全部可见可调**（不再依赖 Python）；
- `printf '{"jsonrpc":"2.0",…}\n' | lightmem-mcp -transport stdio` 手工握手成功；
- **中文写入/召回 UTF-8 完整**（无 `surrogates not allowed`）；
- `go vet ./kernel/` rc=0；`go test -count=1 ./kernel/` 零回归。

**4. 【P0，B 线优先项】修 G8 —— PG 后端 `private` 越权泄露**

E 线在 0.88 实测发现：**PG 后端下，`private` 记忆对同租户任何人（含不传 viewer）可见**。

```go
// 现状 kernel/backend_pg.go:232（Query）与 :315（VectorSearch）同一写法
where := []string{
  "(visibility = $1 OR (visibility = 'shared_user' AND permission->'readers' ? $2) OR tenant_id = $3 OR $3 = ANY(shared_with_tenants))",
}
args := []any{q.Viewer, q.Viewer, q.TenantID}
//          ^^^^^^^^ $1 是“用户名”，却拿去与 visibility 枚举比较 → 该分支恒假
//                              ^^^^^^^^^^ tenant_id=$3 无差别放行，private 行也被放行
```

**规范语义**（`kernel/backend_sqlite.go:512` `canView`，SQLite/Qdrant 均正确，只 PG 分叉）：

| visibility | 正确条件 |
|---|---|
| `private` | `viewer != "" && user_id == viewer` |
| `shared_user` | `viewer != "" && (user_id == viewer \|\| readers 含 viewer)` |
| `tenant` | `tenant != "" && tenant_id == tenant` |
| `cross_tenant` | `tenant != "" && shared_with_tenants 含 tenant` |

**做法**：把 PG 的谓词**逐条对齐 `canView`**（pre-filter，不改 Schema/migration）：

```sql
(
     (visibility = 'private'      AND user_id  = $viewer AND $viewer <> '')
  OR (visibility = 'shared_user'  AND (user_id = $viewer OR permission->'readers' ? $viewer))
  OR (visibility = 'tenant'       AND tenant_id = $tenant)
  OR (visibility = 'cross_tenant' AND $tenant = ANY(shared_with_tenants))
)
```

- `Query` 与 `VectorSearch` **两处都要改**；参数按需调整为 `$viewer`/`$tenant` 两个独立参数。
- **同时**核对 `backend_qdrant.go`（`canView` 正确，**无需改**，但要确认没有同类 SQL/DSL 分叉）。
- **新增 PG 专用真机测试**（env-gated，复用 `eval/e2e/pg/` 的 PG 基础设施）：必须覆盖 **①不传 viewer ②异用户 viewer ③同租户 tenant 级可见 ④owner 本人可见 ⑤跨租户不可见**；**在 0.88 真跑**。
- **补一条反漏网断言**：既有 `TestSearchViewerPrivateIsolation`（`router_search_test.go:235`）**跑在 SQLite 上**，这正是漏网主因 → 新增的 PG 测试必须显式断言"不传 viewer 时 private 命中数 = 0"。

> **安全提醒**：G8（越权读）与 G4（无鉴权、可冒充写）叠加时，18443 一旦暴露到不受信任网络，风险为「任意人可读他人私有记忆 + 可冒充任意 Agent 写入」。**修好前不要把 18443 暴露到内网之外。**
