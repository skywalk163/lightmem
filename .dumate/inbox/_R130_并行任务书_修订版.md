## 2. A 路：codegen 嵌套段落自由变量捕获（主菜）

**目标**：在 R129-E DvClosure 地基之上，让 codegen 生成"嵌套段落能捕获外层自由变量"的 IR。

### 2.1 现状与缺口

**当前流程**（R118-A 一等函数值）：
1. 段名出现在值位 → `_gen_make_function_value` 把 `@_seg_<safe>` 入口指针封成 LV_TYPE_FUNCTION。
2. 调用函数值 → `dv_call_value` 直接调入口指针。
3. **env 永远是 NULL**——嵌套段落里引用外层变量时，codegen 找不到那个变量的 IR 槽。

**缺口**：
1. **自由变量分析**：嵌套段落体里引用的变量，哪些是外层作用域的（不是本段落的形参/局部变量）？
2. **env 打包**：创建函数值时，把自由变量的当前值打包成 env（一个**堆分配的** LightValue 数组）。
3. **段函数入口解包**：嵌套段落的 IR 入口先从 env 解包出自由变量，设到局部槽里，再执行函数体——**前提是调用约定能让入口拿到 env**（见 2.2.3）。

### 2.2 方案

#### 2.2.1 自由变量分析（AST 层）

- 在 `_gen_typed_segment` 处理嵌套段落定义时，先做一次简单的自由变量扫描：
  - 遍历函数体所有表达式，收集所有标识符引用。
  - 减去：本段落的形参 + 本段落内 `设` 定义的局部变量 + 模块级全局标识符（imports / 顶层段名）。
  - 剩下的 = 自由变量（需要捕获的外层变量）。

#### 2.2.2 env 打包（IR 层）

- 创建函数值时，除了传 fn_ptr，再传 env 数组：
  - env 是一个 **`malloc` 分配的 `LightValue[N]` 数组**（**不用 alloca**：env 必须在外层段落返回后仍然存活，供逃逸闭包使用；见 2.4 验收判据）。
  - 每个自由变量按顺序解出来，存到 env 槽里。
  - `dv_make_function_value` 调用时传入 env 指针（R129-E 已支持该入参）。
- **所有权约定**：env 数组的所有权随函数值转移。函数值被 `dv_free` 时释放 env 数组；函数值被深拷贝时，env 数组一并深拷贝（避免共享悬垂与双 free，见 2.3-2）。

#### 2.2.3 段函数入口解包（IR 层）+ 调用约定升级

- **调用约定**（R129-E 遗留缺口，本轮由 A 线定向补齐）：
  - `dv_call_value` 从 DvClosure 解包出 `fn_ptr` 后，**把 `clo->env` 作为第 4 个实参传入段入口**——即入口签名从 `(result, args, num_args)` 升级为 `(result, args, num_args, env)`。
  - 普通顶层段落（非嵌套）`env == NULL`：第 4 参传 NULL，与旧行为完全一致（向后兼容）。
  - 这是 runtime_typed.c 中**唯一**允许的改动点（0.3 红线 1）；其余 runtime 逻辑一律不动。
- 嵌套段落的 IR 入口**第一行**：从 `env` 参数解包出自由变量（按下标索引，编译期已知顺序），设到局部槽。
- 普通顶层段落（非嵌套）：`env == NULL`，入口跳过解包分支。

### 2.3 技术要点

1. **env 的存储形式**：用一个简单的 `LightValue*` 堆数组（按自由变量顺序排列）——不需要字典，因为顺序在编译期已知。
2. **env 的生命周期与拷贝**（对齐 R129-E 遗留注释"env 释放/深拷贝归 R130 管"）：
   - **释放**：函数值 `dv_free` 时释放 env 数组（与 DvClosure 结构体配套）。
   - **深拷贝**：DvClosure 深拷贝（`dv_clone_value` 路径）时，env 数组深拷贝为新数组、新数组随新 DvClosure 释放——**禁止共享同一 env 指针**，杜绝双 free 与逃逸悬垂。
3. **可变捕获 vs 不可变捕获**：本轮先做**值捕获**（捕获时复制当前值），不做引用捕获（Python 的闭包是引用捕获）——与 R127 B7 终局"嵌套段落不能重绑外层变量"的口径一致。如果用户后续要引用捕获，再升级。
4. **lambda（R129-M2）与嵌套段落的关系**：lambda desugar 成命名段落，如果 lambda 出现在嵌套作用域里，自动继承同样的捕获逻辑——不需要单独处理。

### 2.4 验收判据

- 新增 `tests/unit/test_R130_闭包捕获.py`：
  - 嵌套段落读取外层局部变量（值捕获）。
  - **嵌套段落作为函数值返回（创建后外层作用域销毁，闭包仍能读到捕获的值）**——该用例依赖 2.2.2 的堆分配 env，alloca 无法通过本用例（栈帧销毁即悬垂）。
  - lambda（R129-M2）在嵌套作用域里捕获外层变量。
  - 自由变量不与形参/局部变量冲突的边界用例。
  - 捕获 env 的函数值被复制（如存入结构/列表）后，两份拷贝各自可独立调用、均不崩溃（深拷贝语义）。
- 既有函数值调用测试零回归（`test_llvm_first_class_fn.py` 等）。
- 普通顶层段落（非嵌套）行为完全不变（env=NULL 路径）。

## 3. B 路：对象池缓存装饰器真实现

**依赖**：A 线嵌套段落捕获能力跑通后启动。

**目标**：把 `stdlib/对象池缓存.light` 装饰器家族中的 `缓存装饰器` / `记忆化` 从"直通退化"改为真缓存实现。

### 3.1 现状（R127 直通退化版，与实际代码一致）

```光明
# 直通装饰 —— 内部辅助，不导出：接收函数值、原样返回
段落 直通装饰(函数值):
  返回 函数值

# 缓存装饰器 —— 直通退化：返回 直通装饰（不是"返回原函数值"）
段落 缓存装饰器(最大容量 等于 128):
  返回 直通装饰

# 记忆化 —— 直通退化：原样返回传入的函数值
段落 记忆化(原函数):
  返回 原函数
```

> 注：`LRU缓存装饰器`（同为 `返回 直通装饰`）本轮**不翻面**，保持直通退化——理由见 3.3-4。

### 3.2 真实现方案

```光明
段落 缓存装饰器(最大容量 等于 128):
  设 缓存表 为 {}                    # 外层局部变量（将被嵌套段落捕获）
  设 容量 为 最大容量                # 本轮仅占位（不做淘汰），见 3.3-3

  段落 装饰后(原函数):
    段落 包装(*参数):
      设 键 为 转字符串(参数)       # 简单键生成（本轮对拍口径，见 3.3-5）
      如果 字典包含键(缓存表, 键):   # 捕获外层 缓存表
        返回 缓存表[键]
      设 结果 为 原函数(*参数)
      字典设置(缓存表, 键, 结果)
      返回 结果
    返回 包装
  返回 装饰后

段落 记忆化(原函数):
  设 缓存表 为 {}
  段落 包装(*参数):
    设 键 为 转字符串(参数)
    如果 字典包含键(缓存表, 键):
      返回 缓存表[键]
    设 结果 为 原函数(*参数)
    字典设置(缓存表, 键, 结果)
    返回 结果
  返回 包装
```

**关键依赖**：嵌套段落 `包装` 能捕获外层的 `缓存表` 和 `原函数`——这正是 A 线要补的能力。

### 3.3 注意事项

1. **`*参数` 可变参数**：原生腿 O0 是否支持可变参数？如果不支持，需要简化为固定参数（或用字典传参）——实施前先验证。
2. **键生成**：本轮对拍口径下用 `转字符串(参数)` 做键（简单参数：无参/标量/字符串）；多参数、字典参数等复杂键后续再优化，不阻塞本轮。
3. **容量上限**：本轮**不做淘汰**——`缓存装饰器` 的 `最大容量` / `容量` 仅占位（缓存无上限增长），先保证记忆化功能正确与对拍可过；淘汰（LRU/FIFO）留待后续轮次。
4. **`LRU缓存装饰器` 本轮不翻面**：它名带 LRU 却做不了 LRU 淘汰，翻面会导致"名实不符"；且 phase10 无对应翻绿目标（`test_stdlib_phase10.py` 只有 `LRU缓存` 类接口测试，无 `test_LRU缓存装饰器`）。保持直通退化，待做淘汰的轮次再一并翻面。
5. **对拍规范源**：phase10 .py 真装饰器是规范源；若对拍发现 .light 与 .py 语义分歧，**以 .py 契约为准改 .light**，不得反改 .py 测试（除非契约本身有 bug，走 C 线单独记录）。

### 3.4 验收判据

- `@缓存装饰器` 装饰的函数，同参数第二次调用走缓存（不执行原函数）。
- `记忆化` 装饰的函数，行为同上。
- 原生腿与 Python 腿（phase10 .py 真装饰器）在 3.3-5 口径下对拍一致（正式对拍放 C 线，B 线先自测冒烟）。
- `LRU缓存装饰器` 保持直通退化、行为不变（`是函数(LRU缓存装饰器(16))` 为真，调用等价原函数）。

### 3.5 B 线收尾动作

- 更新 `对象池缓存.light` 文件头注释：从"R127 直通退化"改为"R130 真缓存实现"（注明 `LRU缓存装饰器` 仍为直通退化、留待后续淘汰轮次）。
- B 线自测冒烟：`缓存装饰器` / `记忆化` 同参数二调用不执行原函数（对拍正式放 C 线）。
