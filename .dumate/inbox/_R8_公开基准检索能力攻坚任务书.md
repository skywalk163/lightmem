## 1. A 路 — 公开基准英文语义检索攻坚（Q3）

### A.1 背景（根因）

P7-D 报告 §4 已定位三条根因：
1. **英文语义检索**：LME/BEAM 英文长文本，RankFusion 默认权重（针对合成集中文短文本）在英文上匹配弱 → MRR 拉低。
2. **长对话记忆量**：LME 单会话 500 条记忆 + 多 session 跨时间，top-1 排序难命中正确答案。
3. **事实形态差异**：基准 `memory.fact` 是 `question => answer` 或原文 turn，与 `expected_fact`（纯答案）天然错位，文本相似度信号错位。

北极星 M1=1.0000（合成集）说明**链路正确性已达标**；公开基准 0.546 说明**权重/检索参数未针对英文长文本重校准**。这是「参数优化」而非「架构缺陷」，属确定性可解范围（禁 LLM）。

### A.2 范围与红线澄清

- **允许**：新增英文专用权重 JSON（如 `rank_weights_en_benchmarks.json`）、RankFusion 加确定性英文适配分支、embedder 切换（bge-m3 英文向量已可用）、检索 top-K/召回参数针对英文长对话重校准。
- **禁止**：LLM 参与权重搜索/query 改写；改动 `matchFactV4` / `JudgeM1` / `run_kpi.go` 的 MRR 判定口径；改动 `Memory` 既有字段语义。
- **约束**：合成集北极星 M1 不得回归（仍 ≥1.0000）；语义冗余最大降幅仍 ≤5pp；v2 多视图集成 M1 不得低于 0.9661。

### A.3 交付

1. **英文检索权重校准**：产出 `eval/weights/rank_weights_en_benchmarks.json`（针对公开基准回归调参），并在报告中给出调参过程与最终 MRR 提升量。
2. **英文语义检索适配**：在 `kernel/` 或 `eval/polaris/` 新增**确定性**英文适配分支（如英文 tokenize / casefold / 停用词 / 长文本分块索引），零 LLM。
3. **评测器口径对照**：`run_kpi.go` 或新增 runner 跑公开基准，输出 MRR/acc/分桶明细 JSON + 与 R7 基线 0.546 的逐桶对照。
4. **北极星不回归证明**：`polaris_voting.go` 默认态（M1=1.0000）+ 语义冗余（关 path0/path1/path2）+ v2 多视图（0.9661）三组对照，证明 A 路改动未破坏合成集达标。

## 2. B 路 — 公开基准适配 + 时态/事实形态补齐（Q4）

### B.1 背景（根因）

- temporal 桶 MRR 0.552：`recorded_at` 仅 550/650 有效（BEAM 无时间字段），`as_of` 回溯与 `SecondVersion` 双版本记忆在公开基准上未真实验证 → freshness 信号无法正确区分版本。
- open-domain 桶 MRR 0.527：`memory.fact` 是 `question => answer` 或原文 turn，与 `expected_fact` 纯答案错位，文本相似度信号天然错位。
- fact 文本 acc 0%：评测器按 `gotFact == expectedFact` 精确比较必然 0%，是**数据形态差异**，需适配口径而非误报为检索失败。

### B.2 范围与红线澄清

- **允许**：为公开基准样本补 `as_of` 与双版本记忆（确定性规则推断，禁 LLM）；新增「fact 包含 expected」的**适配判定口径**（新增函数，不改 `matchFactV4` / `JudgeM1`）；`memory_kind` 规则推断。
- **禁止**：改动北极星判定口径；LLM 参与 any 规则推断；改动 `Memory` 既有字段语义。
- **约束**：新增适配口径**必须**与北极星口径并存，明确标注「非北极星口径」，不得混用。

### B.3 交付

1. **公开基准适配器**：在 `eval/benchmarks/` 新增确定性适配脚本/代码，为 BEAM/LoCoMo 缺失时间字段的样本推断 `as_of`（规则推断，禁 LLM），并生成 `SecondVersion` 双版本记忆样本。
2. **适配判定口径**：新增 `matchFactV4Benchmarks`（或等价）——「got 包含 expected 文本」判定，作为公开基准的**适配口径**，北极星口径不动。
3. **时态真实验证**：用补齐后的 `as_of` 跑 freshness 信号，重测 temporal 桶 MRR，量化 as_of 补齐的增益。
4. **收口 Q8**：`kernel/lifecycle.go` / `kernel/metrics.go` 既有 gofmt 违规格式化提交（**仅 gofmt，零语义改动**，独立小 commit）。
5. **报告**：`eval/reports/r8b_*.md` + JSON，含分桶 MRR 对照与「真/适配口径」双列。

go run ./run_kpi.go -dataset ./benchmarks/dataset/all.jsonl -report r8b_bench_adapted  # 适配口径

- 由主 agent 合并两路 diff，统一验证默认态不回归 + 门禁全绿后，向用户汇报 commit hash + 指标。
- 用户示意后才 push 到 gitea main；GitHub / GitCode 远端若需同步，另行示意。
- **不得**在收口前自行 push 或合并到 main。
